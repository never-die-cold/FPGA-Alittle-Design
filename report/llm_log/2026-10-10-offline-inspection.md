## 理解门槛：集中讲解

### A. Q01 字段白名单

顶层报文和每个目标分别有允许字段集合。实际字段减白名单得到未知字段；未知字段拒绝。
允许字段不是全部必填，trigger_ref 仍可省略。先检查 dict 才访问字典接口，非法对象抛 ValueError。
合法输入/非法输入以及修复前 FAIL 与修复后 PASS 证明没有放宽已冻结协议。

### B. 共享 ROI

半开框使宽高等于右下−左上，直接对应数组切片，不额外加 1。
灰度和 INTER_AREA 保持交付原函数的语义；长边 42、边缘中位数填充、居中完成 64×64 uint8。
Python round 的半整数取偶数、角点重复和填充值截断都会影响像素，不随意替换。

### C. 训练兼容与独立参考

活跃训练函数保留原签名和默认模式，但把计算交给共享模块，避免训练/部署各写一份漂移。
审计快照保存接收时原字节，清单哈希不变；像素测试抽取原函数而不是比较共享函数与自身。
同环境一致不等于不同 OpenCV 版本或 RTL 近似算法一致。

### D. 原型分类器

加载前检查类别顺序、输入尺寸、网络和预处理标识，避免能加载却喂错像素。
模型 eval 让 BN 使用训练后的统计量，inference_mode 关闭训练梯度；输入 uint8 转 float32/255。
softmax 输出三类相对分数，不是经真实工位校准后的“正确率”。FP32 不是 INT8 部署模型。

### E. 工单规则

工单三类数量必须是非负整数，总数受候选上限约束。实际−期望得到有正负方向的差量。
不确定项优先 RECHECK；完全可用结果才按数量判 PASS/FAIL。高分误分类仍可能误放行，需真实数据验收。

### F. 同一帧处理

定位、所有 ROI 与标注都来自同一 BGR 帧；标注用副本，原图不被框和文字污染。
每个目标保持序号/框/分类/裁剪关联。超上限停止推理并返回未知实际数，禁止截取前 N 个冒充完整结果。

### G. 持久化证据

原始字节、无损帧、标注、逐目标 ROI/hex 与 JSON 清单一起保存。清单和每个产物用 SHA256 检查。
产物解析后必须位于请求目录内部，拒绝越界路径。哈希用于修改检测，不提供可信签名。

### H. 请求复用

请求指纹由来源、权重、参数、代码与版本组成。相同 ID/内容返回原结果；改变参数不能沿用旧结果。
JSON 先写 pending 再改名，完整清单是结束标记。中断目录不会被当成完成或自动覆盖。

### I. 前端回放

--replay 在取相机/创建远端轮次之前分流，只展示经过校验的文件，不能与 MOCK/网络/记录开关混用。
HUD 使用离线来源和实际/工单数，隐藏实时新鲜度与运行按钮。回放不增加联网检查批次。

### J. 测试与复现入口

几何图只检查流程；规则测试替身只控制输入以验证判断分支，不能替代真实模型精度测试。
新六组单独入口保留可选 PyTorch 依赖；旧八组和打包联调检查兼容性。
统一门槛同时要求进程成功、有 PASS、无失败文本，不能只搜到一个 PASS 就算完成。
