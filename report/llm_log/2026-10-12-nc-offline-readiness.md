## 4. 逐段讲解

check_capture_reset_release.tcl先从实际BD读取外部/辅助低有效极性，检查high=1/low=0，再比较外部PS复位、辅助high、dcm_locked high、调试low的实际网络。只有存在且匹配的网络才通过。负例修改实际IP属性或连线，捕获预期拒绝后恢复；最后复查正确设计。外部极性只读，不能假装改值成功。

validate_capture_subsystem.tcl把辅助复位从low移到high，调试复位仍接low；BD基础验证之后再跑上述检查。reset_tests参数执行矩阵并保存恢复正确的BD，不打开硬件目标或生成bit。

audit_c01_build_inputs.py逐条校验归档路径、去重、字节数和SHA256。默认任何不匹配都失败。--recover-to只接受仓库内新目录，尝试CRLF恢复，但候选必须同时满足原清单SHA与大小；否则失败，不覆写旧证据。全部输入成功后才复制清单；失败的部分目录不能当完整包。当前源码漂移和归档完整性分别报告，不能把新包装器归因给旧构建。该工具不证明bit/源码映射或板上功能。

test_c01_build_inputs.py在sim/build内新夹具目录造已知CRLF/LF、篡改和路径负例，断言默认拒绝、显式恢复逐字节等于原文、再严格通过、旧目录拒覆盖、旧归档不改、当前漂移如实列出。接入run_vision_python.sh后14组通过。

所有权候选文档要求完成事件与稳定槽对应、写事务完成和复制窗口保护、cache同步、独立副本、唯一租约/幂等释放及代次失效。软件锁只能阻止软件竞争，不能阻止硬件环绕写槽。没有真实实现/实测之前不冻结或勾选N03。

## 5. 提交前理解题（待用户回答）

① aux_reset_in低有效时接0为何会持续复位？为什么检查必须读取实际BD的极性、常量和连线？
② 68个文件恢复CRLF后，必须同时满足哪些条件才能纳入证据包？这能否证明bit来自当前源码？
③ stream_seq增长、UVC画面正常为何都不能证明某个DDR槽可供PS安全复制？软件锁能否阻止VDMA环绕覆盖？

### 用户回答（2026-10-13）

**① 低有效复位接 0 会持续复位：** “低有效”就是 0 表示请求复位，1 才表示撤销复位；因此接常量 0 相当于一直按住复位键，时钟正常也不能解除这个请求。检查必须同时读取实际 BD 的三件事：极性（该输入究竟是低有效还是高有效）、常量值（连接的常量块实际输出多少）、连线（复位引脚实际连到了哪个输出）；只检查脚本文字或信号名字，可能漏掉工程参数或接线偏差。仓库记录的失败组合正是 C_AUX_RESET_HIGH=0、低有效输入接 0。

**② CRLF 恢复纳入证据包的条件：** 不能仅凭“恢复了 CRLF”纳入。必须满足：每个恢复文件的 SHA256 和字节数同时匹配原始构建清单；全部 98/98 项通过、命令正常结束，失败留下的部分目录不能算完整包；原清单逐字节保留，旧归档和失败记录保留，恢复写入新目录；无路径越界、重复条目或其他内容变化，并用定向 -text 防止 Git 再次转换行尾。这只能证明归档输入与原清单的字节一致，不能独立证明 bit 来自当前源码。当前记录中 96 项一致，两个构建包装脚本已有后续变化；还需要把实际构建输入、构建过程和产出的 bit 建立可追溯关联，bit/hwh/XSA 配对也不能单独替代这条关联。

**③ stream_seq / UVC 不能授权 PS 复制 DDR 槽：** stream_seq 说明监控到几何完整的流握手，没有证明 DDR 写事务完成，也没有原子绑定完成槽号；DMA 停止时仍可能握手后丢弃数据。UVC 正常说明显示支路工作，而显示支路独立于 DDR 捕获。PS 安全复制需要证明：确定的槽已完整写完、相关写事务已完成、整个缓存同步和复制期间不会再次被 DMA 写入；随后才能 invalidate 缓存，复制到独立 PS 内存供下游使用。软件锁不能阻止 VDMA 环绕覆盖——锁只约束遵守它的软件线程，VDMA 不读取 Python 锁；复制慢于一圈时可能前半帧来自旧图、后半帧来自新图，必须建立实际有效的 DMA 停写或槽保护机制。

### 判定（2026-10-13）

三题回答与仓库证据一致，引用复核通过：① 对应 c01-capture-implementation-baseline 的 C_AUX_RESET_HIGH=0、低有效接 0 记录；② 对应恢复包 README 的 98/98 严格复算与“不独立证明 bit 来源”边界；③ 对应 c01-ddr-frame-ownership-v0.md“Python 锁不能阻止 DMA 覆盖、先证明槽再复制”。判定 **3/3 通过**，理解门槛完成，解除“禁止 commit”；本轮离板内容于 2026-10-13 提交入库。
