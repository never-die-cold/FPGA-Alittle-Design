## 2. 模型第一版方案

按接口文档实现 6 个模块（`pc / regfile / alu / decode / if_stage / core_top`），`hello.hex`（RV32IM）作为冒烟程序，tb 期望 `tohost = 142879`。

## 3. 失败现象（真实偏差）

1. **冒烟程序与核能力不匹配**：v0 决策是"先 RV32I"，但 tb 指向的 `hello.hex` 含 `mul/mulhu/divu/remu`，v0 核无法执行；且 `-O2` 把 `×3` 强度削减的教训说明"源码写了什么"不等于"指令流里有什么"。
2. **同步读 BRAM 的流水级界定错误**：若在 BRAM 输出寄存器后再加一个指令寄存器，等效取指两拍→变成三级流水（与"两级"定义冲突），且 PC 与指令错位。
3. **复位期预取导致首指令语义问题**：复位期间 `pc` 保持 `0x80000000`，BRAM 输出已预取 `mem[0]`；若不注入气泡，首条指令可能被执行两次，或 `pc_id` 与指令差一拍。
4. **仿真真实 FAIL：`tohost = 0`**：逐拍 trace 显示 `main` 在 `0x80/0x94` 写入 `0x0000000d`（13），随后 `start.S` 在 `0x38` 用 `main` 的返回值 a0（0）**覆盖同一地址**。工具链阶段文档写的"最终 `tohost = 142879`"从始至终不成立，仿真才暴露。

## 4. 纠错轨迹

| 轮次 | 喂回的信息 | 模型诊断 | 修改内容 | 验证结果 |
|:---|:---|:---|:---|:---|
| 1 | v0 是 RV32I，`hello.hex` 含 M 指令 | 需要 v0 专属固件；用 `-march=rv32i` 从编译期杜绝 M 指令 | 新增 `main_v0.c`（volatile 数组强制 lw/sw）、Makefile 双目标、tb 改指 `hello_v0.hex`（期望 13） | ✅ `readelf -A` = `rv32i2p1`，反汇编无 mul/div/rem |
| 2 | BRAM 输出寄存器后再锁存指令会多一拍 | 同步 BRAM 的输出寄存器**就是** IF/ID 边界；`if_stage` 只做 flush 注入 | `instr = flush_q ? NOP : imem_rdata`；新增 `pc`/`pc_id` 端口与语义说明（设计文档 §5.2 修正） | ✅ 时序与两级流水定义一致 |
| 3 | 复位期 pc 保持、imem 已预取 | 复位后首拍须注入气泡，否则首指令双执行/pc_id 错位 | `flush_q` 复位值 = 1 | ✅ 首条 `auipc sp` 只执行一次，pc_id=0x80000000 |
| 4 | 仿真 FAIL（trace：13 被 0 覆盖） | `main` 写结果、`start.S` 写退出码，共用 `tohost` 冲突 | 拆分 `tohost`（结果）与 `tohost_exit`（退出码）；tb 双断言 | ✅ `PASS: tohost = 13, tohost_exit = 0` |

## 5. 最终结论

**v0 核 RTL 全量落地并用 iverilog 实测通过**：

- 模块：`pc` / `regfile` / `alu` / `decode` / `if_stage` / `core_top`（RV32I；M 接口 `muldiv_op`/`stall` 预留）
- 冒烟：`bash sim/scripts/run_iverilog.sh` → `PASS: tohost = 13 (0x0000000d), tohost_exit = 0`，exit 0
- 程序观测约定：`tohost=0x80003FF0` 结果值、`tohost_exit=0x80003FF4` 退出码（`main.c` 的 RV32IM 版 142879 待补 M 后启用）
- 设计文档已同步修正：`if_stage` 端口（`pc`/`pc_id`）、flush 语义、复位气泡、冒烟判据、待办勾选

**验证方式**：`sim/scripts/run_iverilog.sh` 一键复跑；反汇编 `hello_v0.dis` 覆盖 `auipc/addi/lui/lw/sw/jalr/bgeu/beq` 等 I/M/分支/访存；`readelf -A` 证实纯 RV32I。

## 6. 经验沉淀

- 触发条件：手写 RTL 流水线首次集成、或"仿真结果与设计预期不符"的定位 #skill候选
- 排查步骤：
  1. **同步读 BRAM 的流水级界定**：BRAM 输出寄存器 = 流水边界，别再串一级寄存器；否则级数、面积、时序全变
  2. **带复位的同步存储器要处理"复位期预取"**：复位保持 PC 时存储器输出已就绪，释放后首拍应注入气泡，保证首指令只执行一次
  3. **观测点设计要抗覆盖**：一个 `tohost` 既放结果又放退出码，后写者会覆盖前者——结果与状态分离（本仓库 `tohost`/`tohost_exit`）
  4. **用逐拍 `$monitor` trace 定位"值被改掉"类 bug**：比只看 VCD 或盲猜快得多；trace 中一看 `0x38` 的 `sw a0` 就定位了覆盖源
  5. 冒烟程序要**从编译期锁定指令集**（`-march=rv32i`），别让"源码没用 M 指令"成为口头保证
- 适用范围：换核、换流水深度、换存储器接口均成立
