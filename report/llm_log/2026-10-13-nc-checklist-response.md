## 2. 模型第一版方案

- **重启去重**：`BatchRecords` 启动时扫既有 `records.jsonl` 重建去重键与计数；`AnomalyLog`
  按既有行数续编截图序号；损坏行**大声失败**。
- **快照核对**：服务每轮写 `capture.sha256` 侧车；新 `round_artifacts.py` 三层核对
  （packet 白名单与绑定 → capture 字节哈希 → 引擎 `result.json` 源哈希），含 CLI 供板端核对。
- **重试语义（草案不落码）**：重试键 = `trigger_ref`（已存在字段，不动协议）；本会话内存窗口
  命中回原轮；重启后保留表丢失按新轮；POST 超时重试对 EXE 即"一次采纳"。
- **Q5**：CSV 加 `reasons` 列（`target_limit` = 超限重算的部分计数标识）；C04 记 C03 冻结口径。

## 3. 失败现象

1. 编辑 `records.py` 时 old_string 多带/少带上下文，一次 Edit 把
   `def log(self, mode, event, frame, prototype=False)` 声明行**误删**（函数体孤悬）。
2. `export_records.py` 的 Edit 旧串漏掉中间的 `load_records` 函数 → 匹配失败。
3. 复盘 W06 的教训：来源/资格标记必须**结构性附着**（prototype 无开关），本轮所有新增均沿用。

- 触发条件：审计/证据类存储被跨进程复用；需要"读回来并校验"的产物链；协议外的接口演化。

  （谁权威、哈希锚在哪、不符时行为）→ 协议内能解就不加字段。
- 适用范围：换题目/换板卡仍成立（跨进程去重、哈希核对链、幂等键选择都是通用工程问题）。
