# 大模型协作记录（LLM Collaboration Log）

本目录按 AMD 自主选题赛道 3.3.3.1 / 3.3.5.3 要求，记录项目全程的大模型协作过程。

## 记录什么

**记录"设计决策点"，不记流水账。** 一条合格记录必须包含纠错闭环：

> 提示词 → 模型回答 → 失败现象 → 喂回错误的提示词 → 修正 → 验证通过

以下情况必须记录：
- AI 生成 RTL / 脚本出错并修正的过程（自我纠错轨迹）
- 关键架构决策中 AI 方案的采纳/放弃及理由
- 用综合报告、仿真波形反向定位问题的协作过程
- 智能体工作流（多步任务编排）的设计与调整

以下情况不需要记录：闲聊、查文档式问答、一次性即正确的简单代码。

## 怎么记

1. **平时**：正常用 Kimi Work / OpenCode 工作，AI 产出走 git commit，commit message 注明 prompt 要点
2. **每个工作日收尾**：在当前会话里让 agent 按 `template.md` 模板补写当日记录，文件名 `YYYY-MM-DD-主题.md`（纯英文小写）
3. **每周**：给有可复用价值的记录打 `#skill候选` 标签，作为期末技能包（`skill/`）的原料

## 命名规范

```
llm_log/
├── README.md            # 本文件
├── template.md          # 单条记录模板
├── 2026-09-28-riscv-forwarding-bug.md
├── 2026-10-05-hls-conv-timing.md
└── ...
```

- 文件名：日期 + 英文主题，小写、连字符
- 一条记录聚焦一个问题；一天多个问题就写多条

## 与技能包的关系

期末从 `#skill候选` 条目中提炼四类成果，放入 `skill/`：
1. 提示词工作流（经多次验证稳定的提示词模板）
2. 案例模板（工程骨架 / 脚本模板）
3. 校验脚本（黄金参考比对、资源时序检查）
4. 踩坑清单（触发条件 + 排查步骤）

每条 Skill 须注明：从哪几条日志（哪些失败）中总结得出——这正是日志存在的意义。
