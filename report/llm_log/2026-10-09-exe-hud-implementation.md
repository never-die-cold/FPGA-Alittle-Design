## 3. 失败现象（构建前审查发现一处连带）

1. 打包内容断言按**旧调色板写死** `B < 90`（旧绿 #28A01E 深绿）；v3 新绿 #00E682（B=130）
   会被判"无绿"→ 打包测试必然误报失败。
2. 拟用新判据 `G > B + 60` 在 **uint8 下溢出**（浅灰背景 B=204，+60 回绕成 8）→ 整幅背景
   会被误判为绿色。

## 4. 纠错轨迹

| 轮次 | 喂回的信息 | 模型诊断 | 修改内容 | 验证结果 |
|:---|:---|:---|:---|:---|
| 1 | 构建前审查：调色板变了，旧断言会误报 | 测试与实现的隐性耦合——判据按旧色值写死 | 判据改"通道相对差"式（G 显著高于 B/R），与具体色值解耦 | ✅ 打包测试通过 |

## 7. 追加：v3.1 评审修正（同日，实装后立即评审）

- **用户观察**：AGE 数字每帧跳动（演示模式 0.5s 一轮、数字每秒变十几次）"先声夺人吸引
  注意力，是噪声"；追问"这一栏非要保留吗" → agent 复盘确认三条：与新鲜度条信息重复；
  决策不需要精确数字；精确值已在 `records.jsonl` → **删 AGE 格**（四格改三格）。
- **用户追问**：给新鲜度条加标注说明含义，要求提供"可能的处理方式" → agent 出三张方案对比
  图（A 内嵌 + `FRESHNESS` 标签 / B 内嵌 + `FRESH|EXPIRED` 双端 / C 不标注），并在出图时
  实证了"标签放条外侧、落在浅色桌面上不可读" → 用户选 **A**。
- **教训（追加至 #skill候选）**：动态内容按"变化是否携带信息"分级——**事件驱动的变化**
  （ROUND 每轮 +1）是信息；**无事件也在跳的**（AGE 计时器）是噪声。判别方法：自问"不看它，
  操作员会做错什么决定吗"（AGE：不会 → 删）。另：给控件加说明标注时，先解决"字落在什么
  衬底上"——把控件移入既有深色面板比在浅色画面上抹字更稳。

### 理解门槛（v3.1，1 题）

- 问：`FRESHNESS` 标签为什么必须放在面板里面，而不能像初版那样放在条旁边？
- 用户答："标签落在浅色桌面上看不清。"
- 判定：✅ 通过。补全一般原则：文字可读性取决于其衬底；视频画面背景色不可控，标签与状态
  文字必须给对比度恒定的衬底（面板内嵌 / 衬底框）——与"等待文字深琥珀配深色衬底框"同源。
