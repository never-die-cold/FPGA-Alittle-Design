## 1. 任务与初始提示词

对项目做"挑错挑刺"式体检（对标往届国奖作品），随后针对发现的三个问题给出修复方案并执行：

1. README:87 宣传"行缓存直通、零 DDR 帧缓存依赖"（借鉴 Ultra-Vision），但 README:45-62 架构图画着 `PRE → AXI-Stream/DMA → DDR 帧缓冲 → SOC → OSD → HDMI OUT`——文档内部自相矛盾
2. 应用故事写"工业预检、智能门禁、桌面分拣"，但 board/hardware.md 承认 PYNQ-Z2 无 USB 主机口、实际源是笔记本 HDMI——答辩第一问"门禁现场从哪里接 HDMI"即穿帮
3. README:39 回答"为什么自研核"只有备赛叙事（"考察点有硬内容"），无可量化论证，且芯片上有双核 A9

## 2. 模型第一版方案

- 问题 1：重画架构图为"双路径"——显示/预处理路径零 DDR（行缓存直通），推理路径按需快照（RISC-V 发快照命令，缩放后 KB 级小图进片上 BRAM，CNN 在静态小图上推理，结果寄存器回 OSD）；"零 DDR 帧缓存依赖"精确化为"零逐帧 DDR 回写"
- 问题 2：三档修法（手机转 HDMI / 中档 HDMI 相机或树莓派源 / 纯改叙事）；应用定位改为"片上可交互视觉分析仪"；CNN 目标改为"HDMI 画面字符/数字识别"（与 MNIST 难度相当但演示闭环字面成立）
- 问题 3：给出同器件公开数据对比（PicoRV32 regular ~904 LUT 但 CPI 4–5 / E203 4153 LUT）+ EX 级协处理器耦合论证 + 裁剪代价分析，并立项 CoreMark 实测与 PicoRV32 同工具同器件 OOC 对比

## 3. 失败现象（初版方案的问题）

1. 初版架构图 mermaid 节点嵌套有误（SOC 节点同时当子图名与连线端点），连线语义混乱
2. 初版"为什么自研"段落引用了未实测的 CoreMark 数字——违反项目自身"禁止先写目标后凑数据"铁律；修正为标注"计划口径占位、数据入档后刷新"，并把风险预案写死（CoreMark/MHz < 0.5 则撤回性能话术）
