## 1. 任务与初始提示词

> "我不知道最后要做到什么，我们的HDMI线应该怎么接。，其余的硬件还需要什么"

背景：板卡（PYNQ-Z2）2026-09-20 到货并完成上板冒烟（LED），但视觉/协处理器模块（M2）尚未开工，团队对演示的物理形态与采购清单没有概念。

## 2. 模型第一版方案

先按"通用演示链路"给出建议：HDMI 摄像头 → 板卡 HDMI IN → 处理 → HDMI OUT → 显示器，并列出 HDMI 线、显示器、摄像头采购项；同时按仓库里程碑说明最终交付物（仓库 + 报告 + 演示视频 + `metrics.csv`）与 L1/L2/L3 保底定义。

## 3. 偏差与修正点

本次无仿真/代码失败，但有四处真实偏差，全部由用户选择或文档核对修正：

1. **视频源默认假设偏贵**：第一版默认"买 HDMI 摄像头"，用户选择"笔记本 HDMI 输出"（零成本先跑通，后期再换摄像头）
2. **显示终端方案变更**：用户选择"笔记本 + USB 采集卡"而非独立显示器——采集链路有 50–200 ms 延迟，若不清楚口径会污染端到端延迟指标
3. **发现既有文档自相矛盾**：`board/setup.md` 写"可接 HDMI 观察启动信息 / 接 HDMI 看 IP"，与 `board/README.md`"HDMI IN/OUT 均直连 PL"矛盾——HDMI OUT 由 PL 驱动，不可能显示 Linux 日志
4. **接口硬限制需查官方文档**：PYNQ 官方视频文档明确 Z1/Z2 DVI 前端官方仅支持到 720p（流水线 142 MHz < 1080p60 的 148.5 MHz）、不支持 HDCP；板卡无 USB 主机口，"摄像头"必须是 HDMI 设备——这些约束第一版方案未覆盖

## 4. 纠错轨迹

| 轮次 | 喂回的信息 | 模型诊断 | 修改内容 | 验证结果 |
|:---|:---|:---|:---|:---|
| 1 | 用户选择：视频源 = 笔记本 HDMI 输出 | 零成本、可编程测试图，适合先验通路；后期再评估真摄像头 | 链路改为"笔记本 HDMI → 板卡 IN"，采购清单删除摄像头（降级为可选项） | ✅ 团队确认 |
| 2 | 用户选择：显示 = 笔记本 + 采集卡 | 采集链路延迟不可用于端到端指标 | 明确口径：采集卡仅预览，延迟指标用 OSD 帧计数/时间戳或 GPIO 打点实测 | ✅ 写入 `board/hardware.md` §3.4 |
| 3 | 核对 `board/setup.md` 与 `board/README.md` | 两处对 HDMI 用途的描述矛盾，setup 错 | `setup.md` 三处改为 PROG-UART 串口看日志/查 IP；配件清单补演示硬件并链接 hardware.md | ✅ 已修 |
| 4 | 查 PYNQ 官方视频子系统文档 | 官方只保 720p；无 HDCP；无 USB 主机口 | 源分辨率锁 1280×720@60；禁用受保护内容；docs 写明摄像头必须 HDMI | ✅ 写入 `board/hardware.md` §3 |

## 5. 最终结论

- **演示链路**：笔记本 HDMI 输出 → PYNQ-Z2 HDMI IN →（base overlay 直通 → 自研预处理/推理）→ HDMI OUT → USB 采集卡 → 笔记本回显；Jupyter 走校园网控制
- **采购清单**：HDMI 线 ×2、UVC 采集卡（或显示器）、12V 电源（建议）；可选 USB 功率计
- **验线方法**：线到后先跑 base overlay `hdmi_in.tie(hdmi_out)`，通过后按 `board/logs/` 模板留记录，再进 `src/vision/` 开发
- 落库：`board/hardware.md`（新增）、`board/setup.md`（修正 + 链接）、`docs/prep_checklist.md`（🟡 硬件到位项）、本条记录

## 6. 经验沉淀

- 触发条件：为竞赛/项目规划演示的物理链路、接口与采购清单 #skill候选
- 排查步骤：
  1. 先把"最终演示闭环"写成一句话（谁进、谁处理、谁出），再从闭环倒推配件，避免按"通用常识"默认买摄像头/显示器
  2. 接口能力必须查官方文档原文（分辨率上限、编解码、主机口有无），不要假设开发板都有 USB Host / 都能 1080p
  3. 显示/采集链路若引入额外延迟，必须显式声明"不计入性能指标"，并给出替代测量手段（板上计数器/GPIO 打点）
  4. 最省钱路径优先：笔记本一机两用（源 + 采集回显），真摄像头等通路验证后再评估
- 适用范围（换题目/换板卡是否成立）：成立；任何带视频输入输出的 FPGA 作品都适用
