# Part B 快速乘法方案评估（实现前）

## 1. 实测起点

CoreMark 2K/32 的转发档为 21,926,509 cycles / 10,106,386 retired；分类得到
9,925,509 拍乘法等待、33 拍除法等待。现有握手每条乘法占“启动 1 拍 + 32 次
迭代”，所以动态乘法数为 `9,925,509 / 33 = 300,773`。除法仅 1 次，本轮保持不变。

以下收益均为投影，不是实测。假设退休数、load-use、控制气泡和程序路径不变：

```text
saved = 300,773 × (33 - 新乘法等待拍数)
new_cycles = 21,926,509 - saved
```

## 2. 候选对比

| 方案 | 新等待拍 | 预测 cycles / CPI | 相对当前 fwd | 相对原 nofwd | 资源与时序风险 |
|:---|---:|:---|---:|---:|:---|
| 提前结束，示例平均 24 次迭代 | 25 | 19,520,325 / 1.931484 | 10.97% | 18.22% | DSP 0、BRAM 0；少量检测逻辑，Fmax 风险低；真实收益依赖操作数分布 |
| **Radix-4，两位/拍** | **17** | **17,114,141 / 1.693399** | **21.95%** | **28.30%** | DSP 0、BRAM 0；额外倍数选择/宽加法，LUT 与 Fmax 风险中等 |
| Radix-16，四位/拍 | 9 | 14,707,957 / 1.455313 | 32.92% | 38.38% | DSP 0、BRAM 0；多倍数生成和大 mux，LUT/布线/Fmax 风险高 |
| DSP，内部 3 拍 | 4 | 13,204,092 / 1.306510 | 39.78% | 44.68% | 估计 4–6 DSP48E1、BRAM 0；寄存充分时 Fmax 风险中低，必须实综合 |
| DSP，内部 2 拍 | 3 | 12,903,319 / 1.276749 | 41.15% | 45.94% | 估计 4–6 DSP48E1、BRAM 0；级数更少，DSP 级联时序风险高于 3 拍 |

提前结束的“平均 24 次”只是演示点。若平均有效迭代数为 `k`，等待为 `1+k`，
节省为 `300,773 × (32-k)`；实现前不能把示例 10.97% 当成承诺值。

## 3. 资源依据与实现含义

- XC7Z020 有 220 个 DSP48；现有 v0 core 和 SoC 实现报告均为 0 DSP。32×32→64
  通常需拆成多个 25×18 部分积，4–6 DSP 是工程估算，最终只认 Vivado 报告。
- 当前 v0 core post-route 为 1,606 LUT；v1 尚无同口径实现报告。上述 LUT 风险只能
  定性描述，不能引用为实测增量。
- Radix-4 每拍处理乘数两位，需要正确覆盖 `0/1/2/3 × multiplicand`、额外进位宽度、
  signed magnitude 和四种高半积；除法状态机及所有外部端口保持不变。
- DSP 方案必须在乘法器内部加输入/部分积/输出寄存器。直接使用长组合 `a*b` 而不切拍
  可能伤害 WNS；流水吞吐不是当前目标，核心只需要低延迟和原 start/busy/done 语义。
- 未来 CNN 候选阵列预算约 128/220 DSP；即使核使用 4–6 个仍可容纳，但必须在全 SoC
  资源表中共同记账，不能把“目前空闲”当成永久独占授权。

## 4. 建议与门禁

建议先实现 **Radix-4**：收益确定、无需占用 DSP，预测组合降幅 28.30%，已经超过
25% 尽力目标；复杂度和时序风险显著低于 Radix-16。提前结束可在 Radix-4 稳定后作为
正交优化评估；DSP 方案保留为追求更高性能的第二候选。

实施必须保持 `muldiv` 对外端口和单次 start/done/writeback 语义；新增模块级边界测试，
跑全量回归和双档 CoreMark，并用分类统计核对乘法等待实际下降。任何候选只有在 Vivado
WNS≥0、资源报告入档后才能定稿；当前 WSL 未跑新 Vivado，资源与 Fmax 均为待验证。

## 5. 待用户拍板

1. 采用推荐的 Radix-4；
2. 先做最小改动的提前结束，并补操作数迭代分布；
3. 直接采用 3 拍 DSP 乘法，接受 DSP 占用并优先追求 CoreMark 性能。
