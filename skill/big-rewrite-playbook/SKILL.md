# 大规模重做手册（big-rewrite-playbook）

一句话规则：**重做不是推倒——先冻结设计、用可复现产物评审、新能力走并行通道，已验收链路原样可跑。**

## 适用场景

- 界面 / 渲染层整体重做（参考图 → 产品落地）
- 协议 / 接口演进（旧验证链不能被破坏）
- 文档大规模合并 / 重构
- 任何"想一次性重写掉"的子系统

## 执行清单（按顺序）

### 1. 先定"性价比子集"，写不做清单

- 按**影响面排序**元素（外壳 / 排印 ≫ 光影 / 装饰）；目标定为"可得 70-85%"，**不为最后 15% 换技术栈或挤压功能开发**
- 明确列出"不做的项"（空壳导航 / 真阴影 / 换框架），防止 scope 漂移
- 区分"装饰件"与"功能件"：功能件（对象列表 / 检查按钮）优先做，装饰件后议

### 2. 用可复现产物代替口头描述

- 出图 / 出样脚本：**改一版 = 一条命令**；评审看"现状 vs 提案"对比图，而不是文字描述
- 脚本入库：设计迭代过程可追溯、可重放、可回溯每一轮用户反馈

### 3. 冻结设计再动产品代码；重写范围靠解耦控制

- 定稿图 / 契约评审通过后才开工
- 事先分层（状态机 / 记录 / 渲染分离）→ 重写只换一层，验证过的部分零改动

### 4. 兼容式演进：新能力走并行通道

- 旧链路保持"原样可跑、原测试全绿"（如：旧报文 profile 白名单保持严格，新 profile 另开放行；新版上线前旧版始终可运行）
- 用"新增"代替"替换"，收敛后再清理旧通道

### 5. 重写前先立性能基准脚本

- **估算会翻车**（实测 124.7ms/帧 vs 估算 8-10ms，差 8 倍）；"架构上应该够快"不作数
- 重写必须复测到预算内；热点优化原则：只处理真正需要的数据（直拷 + 局部修正，替代全量逐像素运算）

### 6. 测试连带扫雷

- 表现层常量（调色板 / 字号 / 文案）变更 → 全库搜**写死的断言与绝对色值**；判据改"相对关系"（通道差值 / 形状比例）
- 新资源入包 → selftest 增加"资源存在 + 最小可用"断言（每次构建自动体检）
- 边界陷阱清单：uint8 溢出（比较前升位）、打包数据路径基准（`--specpath` 改变 `--add-data` 解析）

### 7. 大资源先裁剪再入库

- 大字体 / 大素材按目标字符集 / 分辨率**子集化**（17.3MB → 4MB），生成脚本入库保证可复现、缺字可补

### 8. 平台约束提前处理

- 固定像素画布必须声明 **DPI 感知 + 工作区自适应**；否则 200% 缩放的新笔记本上直接"被系统拉伸 + 超出屏幕切割"

### 9. 取舍分界：用户直觉 vs 工程底线

- 视觉取舍听用户直觉（角括号→方框、刻线删除，两轮都按用户意见收回）
- 工程底线自守（对比度衬底、DPI、性能预算不因"好看"妥协）

### 10. 重做过程照走理解门槛 + 回归

- 重做不是流程豁免区：小步交付、讲解出题、全量回归、打包门禁一样不少

## 已验证效果与来源

- **来源**：`report/llm_log/2026-10-08-exe-ui-redesign.md`（三轮评审迭代）、`2026-10-09-exe-hud-implementation.md`（测试连带 / 墨迹对齐）、`2026-10-09-exe-hud-v4-implementation.md`（子集决策 / 性能基准 / DPI / 四个实装坑）、`2026-10-09-exe-export-cjk.md`（资源子集化）、`2026-10-06-vision-sync-protocol-decision.md`（粒度决策）+ 2026-10-10 报文 v1.2 冻结（WC+NC，决策单 D6）
- **效果**：渲染 124.7 → 16.3 ms/帧；窗口 6 → 28 FPS；高分屏切割修复；字体 4× 压缩；协议演进期间旧验证保持全绿（回归 8/8 + 打包五关）

## 与其他 skill 的分工

## 失效条件

- 无可运行验证链路的全新绿地项目（直接按目标架构建，无需兼容通道）
- 用户明确要求"不计成本做到 100%"且资源允许
