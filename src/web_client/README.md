# EdgeSight 网页端

HTML/JavaScript 检查界面，无前端构建步骤。LIVE 模式通过本机 Python 服务连接 PYNQ；合成数据只出现在 LOCAL DEMO。实际验证和剩余问题见 [2026-10-30 联调记录](../../data/logs/2026-10-30-web-live/README.md)。

## 启动

在仓库根目录运行（Python 3.10+，仅标准库）：

```powershell
python src/web_client/serve.py --endpoint http://192.168.50.99:8765
```

打开 <http://127.0.0.1:8000>。可用 `--port` 改端口。服务仅监听本机，静态目录仅为本目录；`/v1/status`、`/v1/config`、`/v1/check`、`/v1/latest` 和本轮快照转发到指定板端，不需要 CORS 或关闭浏览器安全检查。

直接双击 HTML 不能运行 LIVE；ES module 和相机访问需要 HTTP/localhost。板端先运行 `cop_product_service.py`，包路径和参数以板端部署为准。启动会等待真实视频帧，须接好 HDMI IN 并将相机设置为 1280×720。

## 现场操作

1. 等待检查服务连接，页面显示板端 session 和已确认 config。
2. 在“视频设备”选择 USB 采集卡，例如 `USB Video (345f:2109)`，点击“连接采集卡”。首次授权后可再次选择设备；不启用麦克风。
3. 保持零件静止，点击 RUN INSPECTION 或按 C。检查结果来自板端，工单数量沿用服务端配置。
4. 自动检查默认暂停，刷新间隔默认 0.5 秒，可选 0.25/0.5/1.0/2.2 秒。开启后立即检查，每次只允许一个请求在途，不累计批次；失败会暂停自动检查。
5. 手动有效报文每个 `(session_id, check_id)` 只记一次。CSV 从本页内存导出，带 UTF-8 BOM 和会话号；刷新页面会清空本页记录。板端原始轮次另存于服务的 `--root`。

USB 视频仅在本机显示。FPS 根据浏览器实际呈现帧数计量；没有视频时显示 `—`。预览须为 16:9，避免留黑边导致框坐标错位。

界面不再叠加页头/视频判定横幅或视频下方状态条。会话与配置只在 SERVICE 显示，ROUND 只在识别范围卡显示，REC 只在批次卡显示；检查判定保留在日志与 CSV。操作说明放在本文，演示控制仅在 LOCAL DEMO 显示。

未连接 UVC 时，完成检查会显示该报文对应的板端原帧，标为 SNAPSHOT；快照 URL 包含会话和检查编号。它是本轮静态图，不能当作连续视频。UVC 与板端结果只作轮次级叠加，逐帧精确关联未实现。

## 数据源与有效性

- LIVE：真实 HTTP 请求和板端类别、分数、目标编号、工单判定；不生成合成结果。框按报文尺寸缩放，bbox 为半开区间。
- LOCAL DEMO：合成场景，始终标为 MOCK ONLY/PROTOTYPE；模拟断联、配置变化和缺件等按钮仅在此模式可用。
- FILE REPLAY：选择板端 `packet.json` 只读查看，不访问网络或相机；没有加载对应图像，不能用它验证画面与框的对应关系。
- 结果按接收时刻计龄；超龄撤框和计数。会话/配置不符、非法报文、手动检查失败均撤除旧判定。切换数据源后不采纳旧请求的响应。
- 下一轮请求期间保留仍在有效期内的结果，新结果到达后直接替换，不在每次请求开始时清屏。等待首个结果或旧结果过期时，在途检查显示“识别中”；不会延长旧结果的 4.5 秒有效期。实际刷新速度受板端取帧/定位/推理耗时限制，0.5 秒不是硬件推理帧率。离线重连保持约 2 秒间隔；UVC 开启时不下载每轮快照。
- 页面即使暂停自动检查也按约2秒查询状态，单轮在途时顺延；新服务只读返回当前配置号，配置变化撤除旧结果并重置旧手动意图，避免第二个页面引发配置争用。旧服务缺少配置号时兼容首次POST配置握手；多页面恢复需配套新服务。健康失败立即撤框；健康读取不能替代连续推理稳定性验收。本轮修改仅通过离板用例，尚未重新上板。
- `target_limit` 的计数为未知，显示 `--`；判定、数量差额与原因仍保存在检查报文中，界面不再重复叠加展示。
- 类别勾选仅改变本地显示，不下发工单；保留板端原始 T 编号，不重排。工单编辑/下发尚未实现。

亮暗主题按钮使用 localStorage `edgesight-theme`。字体位于 `assets/fonts/`，许可文件随附。
