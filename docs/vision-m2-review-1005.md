## D1 scaler 时钟达标路径（来源 §5.0，commit 0da736d）

- **背景**：real 档 OOC（WIDTH=1280、目标 224×224，NLINES=8/16 均测）WNS −7.4~−7.5 @10ns ≈57.5 MHz，不满足 720p60 的 74.25 MHz。worst path = 行槽读 → 两级 8bit lerp → 输出寄存（约 20 级逻辑），主凶是 lerp 乘法综合成的 9 级 CARRY4 进位链；NLINES 16→8 复测无效（−7.508 vs −7.412），槽 mux 非主凶。x-lerp 提前拍的三次流水化尝试均因 BRAM 一拍滞后与行边界相位连环失配撤销（RTL 无残留）。
- **选项**：
  ① **720p30 首发**：像素钟 37.125 MHz（=74.25/2），57.5 MHz 现状即达标，零工作量；
  ② **插值链切一级流水**：需预寻址重排读时序，约半天，估 75+ MHz（可解 720p60）；
  ③ **乘法改差值形式 / DSP 引导**：收益不确定，无法预估工期。
- **拍板状态**：✅ 2026-09-30 用户拍板——**以 720p60 为正式目标**，30fps 仅作 gate 保底；10/5 评审追认实施排期。
- **推荐（两段走）**：
  - **第一段（保底）**：10/5–10/12 全链按 37.125 MHz 口径串联与演示，gate 稳交付，不等流水化；
  - **第二段（冲 60）**：② 预寻址重排切一级流水立项实施（估半天 + 全量回归）。**验收口径：OOC WNS @10ns ≥ −3.47（Fmax ≥ 74.25 MHz）**，目标 ≥ −1（约 10% 裕量）；落地后像素钟升 74.25 MHz 即 720p60；
  - ③ 不做。
- **物理上限**：720p60 是本板硬件上限（DVI 前端差分引脚速率，`board/hardware.md:39`）——流水线做完最多到 60fps，不存在更高档位；1080p 不在本板讨论范围。
- **余量风险（60fps 口径下）**：② 落地后 scaler 预估 75+ MHz 贴线（对 74.25 仅 ~1%），gaussian/sobel 76 MHz（2.4%）同为贴线——若全系统集成后时序吃紧，对 gaussian/sobel 做同样切拍（移位加链，路径简单、风险低）；演示档可随时一键回退 720p30。
  **2026-10-01 随访实测（real75 档，74.25 MHz 约束）**：gaussian WNS **+0.306**、sobel **+0.219**、scaler（由 real 档 10.534ns 路径推算）≈ +2.9——**三模块 720p60 OOC 全部正裕量，无需切拍**；裕量 ~2% 偏薄，系统级集成后随访。证据 `data/logs/2026-10-01-vision-m2-sprint/vivado-ooc/`。
- **影响**：演示脚本参数化一键切 30/60；A5 逐像素延迟（拍数）与帧率无关，帧延迟（ms）在 60fps 下减半、叙事更优；若 10/10 串联前流水化已 PASS，gate 直接以 60fps 交付（不作承诺）。
- **实施结果（2026-09-30 当日）**：✅ ② 已完成——错半拍预寻址切拍，发射时刻/标记不变，iverilog 10/10 位精确，real 档 OOC **WNS −0.534 ≈ 94.9 MHz**（验收线 −3.47、力争线 −1 均过），新 worst path 为 ph1 拍 BRAM→槽 mux→x 插值→寄存。720p60 达成；gaussian/sobel ≈76 MHz 在 74.25 MHz 口径下余量 ~2.4%，列随访。证据 `data/logs/2026-09-30-scaler-retiming/`。

## D2 HDMI 输入通路（来源 §5.1）

- **拍板状态**：✅ 2026-09-30 用户预批（推荐 a 路径）；条件：原理图终审 ADV7611 I2C 挂载后生效，10/5 追认。
- **背景**：板上 HDMI IN 已有 **ADV7611 解码芯片**（`board/hardware.md:40`），PL 侧拿到的是解码后的并行像素流 + 像素钟——「Vivado 自带 DVI/HDMI IP / 移植开源 TMDS 解码器」两个分支的前提（TMDS 差分直连 PL）在本板基本不成立（待原理图终审，见会前复核清单 #1）。
- **选项**（实质只剩「初始化执行者」）：a) PS Jupyter/Python 配 I2C+EDID（PYNQ base overlay 同路径，`board/hardware.md` §4 验线已验证该链路）；b) 模块一 RISC-V 裸机 C 配 I2C；c) PL 内 I2C 状态机。
- **推荐**：a——开发量最小、与既有验线步骤同一条路径；PL 侧新增一个**输入对齐/归一化**小模块，把 ADV7611 输出整流成 design_v0 §3.1 单元级流约定（vs/hs/de 语义），vision_top 首尾接口就此闭合。
- **影响**：需原理图确认 ADV7611 的 I2C 挂载（PS I2C 还是经 PL）；EDID 由初始化方写（与 D6 分工联动）。

## D3 分辨率 / 帧率 / 色彩空间（来源 §5.2）

- **拍板状态**：✅ 720p + RGB444 已预批（2026-09-30）；帧率项随 D1——**720p60 为正式目标，30 作 gate 保底**。
- **背景**：分辨率已被板卡硬限制收敛——PYNQ 官方文档明确 Z1/Z2 的 DVI 前端只支持到 720p（差分引脚速率限制，视频流水线 142 MHz < 1080p60 的 148.5 MHz），`board/hardware.md:39` 已入档；real 档 OOC 已按 WIDTH=1280 推。
- **选项**：分辨率：720p（唯一可行）/ 1080p（硬限制排除）。帧率：60（时序压力大，见 D1）/ 30（零风险）。色彩：RGB444 / YCbCr422 + 自写色度变换级。
- **推荐**：720p + 帧率随 D1（首发 30）+ **RGB444**——ADV7611 支持配置 RGB 并行输出（含内部 422→444 与色彩空间变换），rgb2gray 前无需加色度变换级（上电实测复核输出格式，见复核清单 #1）。
- **影响**：行宽 1280 定稿（D9）；演示叙事分辨率口径统一为「1280×720」。

## D4 HDMI 输出通路（来源 §5.3）

- **拍板状态**：✅ 2026-09-30 用户预批（推荐 a 路径）；条件：原理图复核输出芯片型号与总线后生效，10/5 追认。
- **背景**：HDMI OUT 由 PL 驱动（`board/hardware.md` §3.6）；PYNQ-Z2 参考手册输出侧芯片为 ADV7511（仓库未入档，**待原理图复核**）。若走板上芯片，PL 只需出并行 RGB@pclk + 时序——§5.3 原文担心的「148.5 MHz 下 10:1 TMDS 可行性」仅适用于 PL 直驱 TMDS 的方案，本板大概率不需要。
- **选项**：a) 板上输出芯片 + PS I2C 初始化，PL 出 24bit 并行 RGB（base overlay 同路径）；b) PL 直驱 TMDS（OSERDES 10:1 + 开源 encoder，仅当 TMDS 引脚直连 PL 才可行）。
- **推荐**：a。720p60 也只需 74.25 MHz 并行时钟，与 gaussian/sobel 的 OOC 76 MHz 同量级，无新增时序风险。
- **影响**：vision_top 出口 = osd_overlay → 720p 时序发生器（vs/hs/de）→ 并行 RGB 总线；时序发生器参数与 D2 输入归一化级共用一套。

## D5 模块三网络输入尺寸（来源 §5.4）

- **拍板状态**：✅ 2026-09-30 用户预批口径——「模块三拍板数值 + 建议 32–64 起步 + 224 留上限仿真档 + NLINES 约束复推 OOC」；具体尺寸仍待模块三（10/5）。
- **背景**：scaler 目标尺寸现为 OOC 占位 224×224（`sim/scripts/synth_vision_ooc.tcl`）；训练侧全链演练已通（`dev/verify` @ 8efb17f：极简 CNN 8×8 两类占位网络，训练→INT8→hex 一键复现），**正式网络/尺寸正是 10/5 拍板项**；cop_top RTL 10/5 开工，MAC 阵列维度未定（`docs/module3-model-training.md` §5.4）。
- **vision 侧硬约束（拍板前必须知道的耦合）**：
  1. DW/DH/NLINES 是 elaboration 参数，**非运行时寄存器**——拍板后改 generic 复推 OOC 即可，无 RTL 风险；
  2. 行槽约束 **NLINES ≥ SH/DH + 2**（SH=720）：DH=224→NLINES=8；DH=64→NLINES=16；DH=32→NLINES=32。32 槽估算全链 BRAM 从 ≈10 涨到 ≈22 BRAM36（约 7%→16%），仍充裕；且 D1 已证槽 mux 非时序主凶，复推风险低；
  3. 吞吐 1 像素/2 拍（缩小档），目标小图无压力。
- **推荐**：拍板权在模块三（jianglibo + 训练侧按 MAC 阵列预算定数值）；vision 声明上述约束。倾向 **32–64 起步**（协处理器首网小而稳），224 保留为上限仿真档。
- **影响**：拍板后 vision 一行 generic 改参 + OOC 复推 + design_v0 §7 回写；watercopper 的 scaler 黄金参考第二尺寸档（design_v0 §6）也依赖此数值。

## D7 sobel 接入位置（文档外）

- **背景**：sobel 单元级 PASS 但未接 vision_top（R0 bit3 仅预留）；design_v0 §2 初稿把 sobel 画在 scaler 之后；`sobel.v` 头注提「若评审决定抽公共窗口模块，与 gaussian 一并重构」。
- **选项**：a) 缩放前（gaussian 后，1280 行宽）；b) 缩放后（224 行宽，行缓存省约 20 倍）。
- **推荐**：**a**。理由：边缘检测在全分辨率上演示视觉效果更好；窗口装配/冲刷与 gaussian 同构，接法照抄；缩放后 224 小图边缘信息已损失。代价：多 2 片 1280×8 行缓存（≈1 BRAM36，充裕）。拓扑：rgb2gray→gaussian→[R0 bit3 选 gauss 直通或 sobel]→scaler→osd。
- **公共窗口模块重构**：M2 主线不动（已 10/10 PASS），列 10/12 后重构项，评审追认即可。
- **影响**：vision_top 串联按此拓扑实施，交付依赖见根目录 [全局看板](../plan.md#32-交付看板)；R0 位定义随 D12 一并冻结。

## D10 配置总线与跨时钟（文档外：axi_regs.v 头注 + §3.1）

- **背景**：axi_regs 单元级单时钟域 PASS；真实配置时钟域未定（`axi_regs.v:4`「由 vision_top 评审定」）；§3.1 初稿约定 2FF 同步器。另外存在一个**主体空白**：根 README 软硬件划分把「任务控制」给 PL 内 RISC-V（模块一），而演示调参直觉上是 PS Jupyter——谁写 axi_regs 本身没有定；且模块一 design_v0 无任何 vision/总线接口条款（跨模块契约空白，盘点 grep 零命中）。
- **选项**：a) PS 经 AXI_GP 直挂（Jupyter 调参，演示直观）；b) 模块一 RISC-V 总线直挂；c) 双 master 经 AXI 互联。
- **推荐**：M2 gate 用 **a**（演示 A1/A4 动效最直观，PYNQ 标准路径）；跨时钟用 2FF（配置低频，axi_regs 已有读写通道序列化握手）；c 列 M3 集成项。**评审需拉通**：模块一 SoC 总线时钟频率、互联形态、地址映射窗口（建议模块一到场）。
- **影响**：vision_top 中 axi_regs 时钟域定为 s_axi_aclk（PS 来的 100 MHz 级），与 pclk 异步。R0 开关类标量 2FF 同步即可；多字节参数（box/roi）不做逐位同步，靠「帧首锁存 + 帧边界生效」语义吸收跨时钟位偏差（写入延迟 ≪ 帧周期，位偏差在下一帧开始前早收敛）——**该论证需评审显式确认**，若不认可则需加握手/quota 方案。
