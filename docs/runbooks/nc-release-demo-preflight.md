## 接收JL/WC交付包时的门禁

| 包 | 必须一并交付 | NC拒收/退回条件 |
|---|---|---|
| JL计算/集成 | 精确源码commit/dirty清单、bit/hwh/XSA、地址/复位/时钟、固件、模型/参数布局、SHA/CRC、固定输入/逐层黄金、仓库入口/退出码/日志 | 缺指纹或黄金；控制器OOC当集成报告；TB hex当生产DMA包；旧核/视觉回归退化 |
| WC软件 | 完整EXE目录、PS应用/依赖锁定、启动配置、正式模型/预处理/阈值身份、协议版本、服务/记录/导出/恢复说明、负例回归 | 只交EXE漏_internal；软件编号冒充R12；FILE伪装硬件；未完整计数当实测 |
| 数据/模型 | 数据split/会话/实物审计、人工GT复核、正式INT8权重/量化/阈值、逐类评估、哈希与导出命令 | test参与调参；诊断未训练权重当正式模型；真实精度无原样本/分母 |

每包记录接收时间、交付者、完整文件清单、SHA、已知限制、验收结论。更换任一bit/模型/固件/软件形成新候选版本并指定复验范围，不混用旧通过记录。

## Windows目标机复现（N13）

1. 完整拷贝候选运行目录，在新路径校验文件清单与SHA；先selftest，再FILE回放，后接真实设备。
2. 从操作手册启动，核对UVC实际设备/模式与服务地址/会话/工单回执，执行正常、异常、恢复、记录和导出。
3. 记录OS/机器、是否预装Python/依赖、网络/权限、完整路径；当前开发机清除环境变量复验不等于无开发环境机器验收。
4. 逐轮复核权威capture、实际判定、记录/截图/CSV；原图与上下文截图角色不同。
5. 按预先约定时长持续运行，保留所有错误；重启/重载/断连修复后再验，失败不覆盖。
6. 演示包与正式数据分开；MOCK、FILE、PROTOTYPE不进入LIVE硬件指标。

## 演示分镜（时长是建议，可调整）

| 段 | 建议时长 | 画面与要证明的事 |
|---|---|---|
| 接线/版本 | 30s | 实物拓扑、当前bit/模型/软件版本；不使用剪辑掩盖手动加载 |
| 正常检查 | 60s | 分散三类→新capture→框/类别→真实核判定→一条批次；权威原帧可复核 |
| 缺/多/错料 | 60s | 三个独立轮次及正确差额，工单/对象/记录对应 |
| 复检边界 | 40s | 触边或超10，明确RECHECK/未完整计数，不能把0写成实测 |
| 故障恢复 | 40s | 断联/过期撤框，恢复新轮次；不静默旧框 |
| 导出与指标 | 30s | JSONL/CSV/异常截图，解释来源、分母与阶段延迟 |

离板可以用当前候选演练界面/旁白；整段恒标PROTOTYPE。最终实机录像须另拍，未接入核判定时不说“核已执行”。

## 答辩自查

- 能从证据讲清核四档功能/CPI与转发收益，不能把乘法或分支预测收益归给转发。
- 能指出HDMI显示、CAP stream_seq与DDR完成/槽所有权三者区别。
- 能说明软件frame_id、轮次与UVC同帧边界，以及capture权威原图。
- 能说明16能力/10策略、超限RECHECK与未完整计数，展示[#75](https://github.com/never-die-cold/FPGA-Alittle-Design/issues/75)修复验收状态。
- 能说明诊断黄金、正式模型、FP32分数与INT8 margin各自的身份；控制器OOC不代表全系统资源/时序。
- 能拿出仓库一键入口、固定输入、原始日志和失败历史，复现结果而不依赖聊天记忆。
