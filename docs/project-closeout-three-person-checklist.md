# 三人并行待办：从当前版本到项目收工

制定日期：2026-10-10；最新核对：2026-10-13，`3e2e1c9`（PR #69/#70/#71 已合并，本轮新增尚未提交）。初始基线 `c292038`（PR #68）保留在历史证据中。
用户最新分工优先于旧计划中的板务和训练人员安排：全部上板工作由用户负责，另外两人只做离板工作。
本清单是执行分工与验收拆解，不自动修改现有硬件、接口、模型参数或里程碑。

## 1. 人员与边界

| 人员 | 主线 | 负责内容 |

| 用户 / never-die-cold（NC） | 上板与最终验收 | 硬件、镜像、接线、位流加载、相机定标与采集、实机部署、故障复现、指标实测、演示录制和最终提交 |

| watercopper（WC） | 离板应用链 | 数据标注/审计、定位与统一 ROI、PS 服务与驱动适配、EXE、协议/异常测试、应用发布包、报告和复现材料 |

JL 从 WC 接收审计后的真实 ROI；WC 从 JL 接收模型、量化与推理驱动契约。
NC 提供硬件能力、原始帧和实测日志；两人写脚本/修复软件，NC 在板上执行。
JL 可以在电脑上生成 bit/hwh；下载到板卡、在线 ILA、实机网口和串口操作均由 NC 执行。
已有核主体不重做；新协处理器集成必须保证其回归不退化。

## 8. 每次交付和最终完成标准

每个交付包必须有：源码提交、产物/参数SHA256、仓库一键脚本、输入与期望、原始日志/退出码、已知限制。
软件/RTL作者做离板验证，NC做实机验证；失败时NC提供最小输入、版本和日志，JL/WC各自修复。
跨目录与接口变动先同步，AI代码继续按仓库小步和理解门槛；经PR合并，禁止强推覆盖分支独有提交。
完成一项只在其通过条件满足后勾选；“脚本能跑”“已有截图”“打印PASS”均不能替代对应验收。

项目收工必须同时满足：

- [ ] 真实相机/集成位流/CNN/核判定/服务/EXE链路在目标设备验证。
- [ ] 正式数据、模型、量化、RTL/固件、位流、服务和EXE版本能完整追溯。
- [ ] 工业正负例、重复/旧结果、断联/恢复与长时间运行证据齐全。
- [ ] 定位、分类、工单与性能/资源指标有原始数据，目标和实测分开。
- [ ] 最终发布包在目标电脑复验，手册从接线到导出可执行。
- [ ] 报告、Skill、演示视频、代码/权重/配置、复现清单、已知限制和备份齐全。
- [ ] 三人能解释各自实现和交接；最终提交完成并保存回执。

首版以外：连续运动/跟踪、逐帧精确叠加、缺陷/尺寸检测、更多类别、多种复杂背景及非必要性能优化，完成主线后按余量处理。
