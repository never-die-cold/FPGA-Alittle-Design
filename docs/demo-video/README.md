# 演示视频方案（实验室版，3 分钟，2026-11-03）

> 硬性规格：**MP4 / H.264 (AVC) / ≤3:00 / ≤300MB**。
> 场景：**学校专门实验室**——目标观感"正式、专业、可交付"，不是桌面随手拍。
> 本文档 = 分镜 + 逐字稿 + 拍摄参数；执行步骤见 [runbook.md](runbook.md)，照片见 [photo-plan.md](photo-plan.md)。
> 状态口径 **2026-11-03**：网页端已与板端真实链路联调成功，但**连续轮次不稳定**（10-30 记录第 5 轮 TASK_ERROR、随后 MM2S DMA 超时，根因未定位）；模型对当前工件输出低分，判定为 RECHECK。方案按此设计，**不作任何"板上识别通过"的表述**。

## 一、叙事主线（先定调，再拍）

三分钟只讲一件事：**这套系统在证据不足时拒绝放行**。

多数演示片在展示"识别得多准"，我们展示"**不确定时的处理方式**"：结果带会话、配置号与 4.5 秒年龄窗，过期即撤框；低置信就判 RECHECK，不调阈值凑 PASS。评委记住的不是又一个检测 demo，而是一条**敢说"我不确定"的工业检查链**。

分两条线交替：**硬件与自研（可信）** + **网页端交互（可看）**。前者给实验室实拍与数据，后者给真实上板界面。

## 三、拍摄纪律（由当前系统状态决定，必须遵守）

1. **只开一个浏览器页**。审计报告 F01：同会话第二个页面会抢先写配置，导致当前页面 `config` 不符而断开，只能重载恢复。拍摄前关闭所有标签页、手机端页面和其他连过板端的电脑。
2. **每段单独录 2–3 遍**。板端已知会在第 5 轮左右出现 TASK_ERROR 或 DMA 超时；不要试图一口气录完整流程，按分镜分段录，失败就重开服务再录。
3. **绝不伪造 PASS**。当前模型输出低分、判定 RECHECK，是真实行为。片中把它作为"设计的安全行为"讲出来；**不要**用 LOCAL DEMO 的合成 PASS 冒充板端结果。LOCAL DEMO 只允许用于纯 UI 交互镜头，且必须打角标。
4. **不拍"取走零件→判定翻转"的因果镜头**。当前判定为 RECHECK，不存在随工件变化的 PASS/FAIL，硬拍会变成误导。
5. 结果**4.5 秒过期撤框**，所有含框镜头必须在结果到达后立刻录，不能等。
6. 字幕与口播统一用"复检（RECHECK）""低置信"这类中性词，不用"误判""失败"。

## 五、逐字稿（约 660 字 ≈ 2'38"@250 字/分）

> 与分镜逐句对应；S5、S6 为该版本的核心段落，语速放慢半拍。

（S0）这是一套面向受控工位的紧固件识别与工业检查系统：从图像预处理、CNN 推理到 RISC-V 判定，全链路自主设计。

（S1）系统分三层。PL 里的视频流水线完成 720p 采集与三路分流；128 个乘加单元的 INT8 协处理器做逐目标分类；自研 RISC-V 核负责调度、计数与工单判定。板端与网页端之间用轮次协议通信，每条结果都绑定会话、配置号和年龄窗。

（S2）这是真实的硬件链路：树莓派摄像头经 HDMI 进入 PYNQ-Z2，板卡的 HDMI 输出经采集卡送入笔记本。

（S3）零件自由分散摆放，不做固定工装。

（S4）网页端接入采集卡的实时画面。屏幕上的目标框、类别和置信度来自板端轮次，不是本地合成。

（S5）手动触发一轮检查，按钮即时反馈排队和运行状态。这一轮板端给出六个目标，但置信度都低于阈值，系统判定复检，并写明原因。我们没有为了好看去调低阈值——不确定的结果，不能当合格放行。

（S6）结果的有效期只有四点五秒。超龄、断联或者配置变化，画面立即撤框。宁可显示等待，也不留一个过期结论在屏幕上。

（S7）每轮手动检查落一条批次记录，自动轮不重复计数；一键导出 CSV，Excel 直接打开，形成可追溯的检查闭环。

（S8）底层是自研的 RISC-V 处理器：三级流水、数据转发和分支预测。四十四组体系结构测试全部通过，每兆赫 1.974 个 CoreMark，布线后时序收敛在八十六点八兆赫。

（S9）CNN 协处理器采用全整数通路，四例黄金向量在板上与参考逐位一致。它证明的是整数链正确，正式识别精度仍在收敛。

（S10）EdgeSight，让每一次判定都有据可查。

## 七、剪辑与后期

- 剪辑：剪映专业版；时间线 1920×1080 / 30fps。
- 节奏：单镜头 ≤5 秒；实拍与录屏每 20–30 秒交替；S5/S6 保持长镜头不切碎（这两段的说服力来自连续）。
- 录屏细节：鼠标加高亮圈；右侧栏小字用 1.3× 放大框（识别范围表、判定原因）；日志关键字（RECHECK、low_score）加下划线动效。
- 角标：S1 架构图右上"系统架构"；S4–S7 右上"LIVE 实机"；若任何镜头用了 LOCAL DEMO，必须换成"界面演示 · 合成数据"并降低到不超过 5 秒。
- 数据字幕：S8/S9 用等宽大号数字，与 `docs/tech-report` 完全一致，逐个核对。
- 音频：配音单独录（衣柜/棉被吸音，手机+线控麦，离麦 15cm），人声 -6dB 峰值；BGM 商用免费曲目，压至 -22dB 并开人声闪避；全片 -16 LUFS。
- 字幕：全程中文硬字幕，术语统一（协处理器 / 轮次 / 复检 / 置信度）。
- 导出：H.264 High、1080p30、10000 kbps、AAC 320kbps → 3 分钟约 200MB，必过 300MB 限制。

## 八、风险与预案

| 风险 | 触发条件 | 预案 |
|:---|:---|:---|
| 板端轮次失败（TASK_ERROR / DMA 超时） | S4–S7 期间日志出现红字、框不出现 | 按纪律第 2 条：停录 → 重开产品服务（板端 `cop_product_service.py --root <新目录>`）→ 重新连接采集卡 → 重录该段；同一段最多重试 3 次 |
| 第二个页面抢配置（F01） | 页面突然断开 / 配置不符 | 关闭所有其他浏览器页与设备；重载页面 → 重新连接采集卡 |
| 结果始终为低置信 RECHECK | 全片 | **按设计讲**（S5 台词），不调阈值、不换合成数据 |
| 采集卡不识别 | 设备列表为空 | 重插 USB、换口；用 `list_dshow_video.ps1` 确认设备索引 |
| 板端完全离线 | 8765 无服务 | 视频仍可完成：S4–S7 改用 10-30 保存的实板快照（SNAPSHOT）+ 明确角标"实板快照"，并在片尾字幕标注"实板联调视频见附件" |
| 灯光频闪 | 实拍出现横纹 | 快门改 1/100，或关闭顶灯只用 LED 面光 |
