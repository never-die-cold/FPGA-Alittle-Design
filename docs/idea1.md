EdgePilot —— 视觉引导机器人控制 SoC（EdgeSight 融合扩展方案）

> 来源：2026-09-10 与 Kimi 的讨论记录整理。核心结论：先做 EdgeSight，后接机器人控制，融合为"感知-决策-执行"全链路 FPGA 作品。

背景

- 原项目：EdgeSight（PYNQ-Z2 上自研三级流水 RISC-V 核 + HDMI 图像预处理流水线 + CNN 推理协处理器），全国大学生嵌入式芯片与系统设计竞赛 FPGA 创新设计赛道（AMD 自主选题·初级组）。
- 灵感来源：Microduck（Hugging Face / Pollen Robotics 的开源双足机器人，399，核心是其开源 RL 技术栈：MuJoCo 仿真训练 → ONNX 导出 → 真机部署）。
- 结论：不换赛道、不换比赛，而是在同一 FPGA 赛道上把 EdgeSight 与机器人控制融合。

融合方案一句话简介

在 PYNQ-Z2 上实现"摄像头进、电机出"的视觉引导机器人控制 SoC：自研 RISC-V 核统一调度，视觉流水线负责"看清目标"，策略/控制协处理器负责"算出动作"，PWM 直接驱动执行机构，全链路确定性延迟。

系统架构

```
HDMI 摄像头 → 预处理流水线 → CNN 检测（目标在哪）
                                    ↓
IMU/编码器 → 姿态解算 → RISC-V 核融合决策 → MLP 策略/PID → PWM → 电机
```

- 视觉伺服（Visual Servoing）的端侧硬件加速。
- 模块复用：EdgeSight 三大模块（RISC-V 核 / 预处理流水线 / 协处理器）全部保留。
- 新增模块（中小规模 RTL）：IMU 接口 + 姿态解算（互补滤波/简化 EKF 定点实现）+ PWM 输出 + 编码器捕获。

为什么融合是加分项

1. 故事完整："感知-决策-执行"全链路 = 具身智能核心叙事，系统级作品 vs 模块级作品的分水岭。
2. 对比基线更有说服力：三组对比——纯 ARM 软件全链路 / 只加速视觉 / 全链路 FPGA 加速，端到端延迟可差两个数量级。
3. 演示效果强：现场能看到"会动的东西"，远比"摄像头进、框出"直观。

演示闭环建议：视觉跟踪云台 / 视觉平衡杆

- 摄像头识别特定颜色球（或 AprilTag），CNN/色块检测输出目标坐标。
- 目标坐标作为控制器输入，PWM 驱动双轴舵机云台始终对准目标。
- 进阶：球滚到哪儿，桌面小车/平衡杆跟到哪儿。
- 机械部分只需两个舵机 + 云台支架，避免陷入机器人本体（机械/装配/调参）的坑。

实施顺序（关键）

1. 先按原计划完成 EdgeSight（M1–M3 里程碑不变），全部指标实测留档。
2. 控制侧作为 M3 之后的增量模块接入。
3. 天然形成 L4 保底：控制侧翻车仍有一个完整的 EdgeSight 可交。

降级策略（在原 L1–L3 之上扩展）

| 版本 | 内容 |
|:---|:---|
| L1 目标版 | 视觉 CNN 检测 + MLP 策略协处理器 + 控制闭环全链路 |
| L2 稳健版 | 砍 CNN 协处理器：纯 RTL 色块/质心检测接控制（链路更简洁，控制环路 10–30fps 足够） |
| L3 保底版 | EdgeSight 原版完整交付（视觉部分） |
| L4 | 控制对象走 HIL 仿真（PL 跑控制，PC/PS 跑物理仿真），无实物 |

核心指标

- 端到端"像素到 PWM"延迟（FPGA 微秒级 vs ARM 软件毫秒级），全链路对比 ARM 软件基线。
- 保留 EdgeSight 原有指标：CPI 优化、Fmax/WNS、预处理延迟、推理加速比、资源占用。

风险与注意

1. 不要并行开工：先收 EdgeSight 的尾，再接控制；融合的系统集成复杂度主要在跨模块调试（"视觉对了但控制抖"）。
2. CNN 检测别贪大：控制环路帧率要求低，小网络甚至纯 RTL 检测即可。
3. 控制对象轻机械化：云台/平衡杆/倒立摆，绝不自己攒双足机器人本体。
4. 决赛 Verilog 上机考核不受影响：RISC-V 核仍是"芯片设计含量"的根基，继续每周刷 HDLBits。
