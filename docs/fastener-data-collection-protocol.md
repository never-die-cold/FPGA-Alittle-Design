## 1. 采集前置条件与硬约束

| 项 | 约束 | 出处 |
|:---|:---|:---|
| 取帧路径 | 必须经 PYNQ HDMI IN 链路取帧（base overlay `hdmi_in.readframe()`），不用 Pi 侧直接存图——数据集像素 = 部署像素 | board/hardware.md §1/§3 |
| 分辨率/帧率 | 1280×720@60；Pi 侧 config.txt 锁 `hdmi_group=1`/`hdmi_mode=4`；上电顺序 PYNQ 先、Pi 后 | board/hardware.md §3.7 |
| 相机设置 | Camera Module 3 标准 75° AF 日光版；AF/AE/AWB 用默认自动（与部署一致），任何手动改动记入 manifest | board/hardware.md §2 |
| 机位 | 三脚架/桌面支架固定，工作距离 40–80 cm；训练/测试/演示同机位 | board/hardware.md §2 |
| 摆放 | 自由分散且互不遮挡（不接触、不堆叠）；接触/遮挡场景只作「提示复检」负样本 | plan.md §1.3 |
| 首版类别 | 螺栓 / 螺母 / 垫圈（3 类，与候选网 FC 64→3 对齐） | docs/module3-model-training.md §3.5 |
| 输入尺寸 | ⚠️ 64×64 待 10/5 拍板（96×96 为升级档）；本文门限以 S 表示，默认 S=64 | docs/module3-model-training.md §3.5 |

## 2. 机位与工作距离定标（到货后第一项实测）

1. 桌面放刻度直尺/坐标纸，按 40 / 50 / 60 / 70 / 80 cm 五档距离各拍 1 帧。
2. 从帧内量出「像素/毫米」换算，得每档 mm/px；记录视野覆盖范围（能否罩住 ≥30×20 cm 摆放区）。
3. 门限（⚠️ 建议值，拍板后冻结）：最小零件（垫圈）外径在帧内 ≥ 2S px（S=64 → ≥128 px），保证 bbox 裁剪缩到 S×S 时细节不塌。
4. 选定一档距离使门限成立且摆放区完整入画，锁定支架位置并在支架与桌面画定位标记；此后所有会话复用该标记。
5. 产出：`data/datasets/calib-YYYYMMDD/` 存五档原始帧 + `calibration.md`（每档 mm/px、视野、选定档位与理由）。

## 3. 光照矩阵与背景、最小间距实测

### 3.1 光照条件矩阵（每格 ≥3 帧）

| 编号 | 条件 | 典型影/光 | 采集目的 |
|:---|:---|:---|:---|
| L0 | 均匀漫射（顶灯 + 白纸/漫射罩柔光） | 无明显投影 | 部署主条件，正式训练/测试主数据 |
| L1 | 单侧强台灯 | 侧向长影 | 阴影分裂/合并压力用例 |
| L2 | 顶光直射（去漫射） | 金属高光斑 | 反光分裂压力用例 |
| L3 | 自然窗光（背窗/侧窗各一组） | 混合 | 鲁棒性补充 |

原则：L1–L3 用于划定「支持条件」边界——实测后决定是改进布光（加漫射）还是归入「超条件提示复检」（plan.md §3.4）。

### 3.2 背景实测步骤

1. 候选背景 ≥3 种：深色哑光垫 / 浅灰哑光垫 / 木纹桌面（与最终演示用同一块）。
2. 每种背景 × L0，摆固定 5 零件组合（3 类各 1–2 个、随机朝向），拍 10 帧（每帧轻微扰动位置）。
3. 用现有 ARM 定位基线（`docs/arm-localize-runbook.md`）跑检测，人工核对 GT，记录漏框/多框/框抖动。
4. 选「漏框=多框=0」的背景为默认背景；其余背景数据保留（供鲁棒性）。

### 3.3 最小间距实测步骤

1. 定义间距 = 相邻零件边缘距，以最大零件直径 D 为单位。
2. 同批同款零件，按 0.5D / 1D / 2D / 4D 四档摆放（每档 ≥5 帧、≥2 种随机布局），背景与光照固定为 3.2 实测默认。
3. 同 3.2 第 3 步跑基线：统计「两件并作一框（合并）」「一件裂成两框（分裂）」次数。
4. ⚠️ 取「连续 30 帧零合并、零分裂」的最小档为最小间距工程参数，回填 plan.md §1.3 待冻结清单；0.5D 档数据保留作拒绝样例。

## 4. 采集批次设计与命名规范

### 4.1 批次矩阵（train/val/test 通盘覆盖，逐格计数入 manifest）

维度：类别(3) × 光照(L0–L3) × 朝向（螺栓：轴向/斜置/头朝上；螺母垫圈：正扣/斜扣）× 数量档（1 / 3–5 / 8–10 个/帧）。

- 每格 ≥10 帧，每帧逐目标标注 bbox；总帧数目标 ⚠️ 首轮 ≥600 帧，视首轮基线精度加采。
- 数量上限对齐 D5 帧预算假设（10 目标），单帧最多 10 个。
- 帧间扰动：每帧重新随机摆放（避免相邻帧近似重复）；同一摆放只拍 1 帧。

### 4.2 集合划分（防泄漏，硬规则）

1. **按拍摄会话划分，不按帧划分**：同一会话的帧只进一个集合；测试集必须用独立会话（module3 文档 §3「避免相邻视频帧混入各集合」的可执行化）。
2. 优先**按实物个体划分**：同类零件有多个个体时，部分个体只进测试集。
3. 比例 ⚠️ train/val/test ≈ 70/15/15（按帧数）；val 用于量化校准与超参，test 只评一次。
4. 空场景、错料、超最小间距拒绝样例只进 test/联调集，不进 train。

### 4.3 目录与命名（`data/datasets/`，首次建立）

```
data/datasets/fastener-v1/
├── README.md                    # 版本、总帧数、划分口径、已知缺陷
├── manifest.csv                 # 全量清单（一行一目标）
├── raw/sess-YYYYMMDD-HHMM-<L0..L3>-<bg>/frame_00001.png   # 720p 原帧，PNG 无损
├── gt/sess-同上/frame_00001.csv  # obj_id,class,x0,y0,x1,y1
└── crops/sess-同上/<class>/frame_00001_obj01.png          # bbox 裁剪原图，不预缩放
```

- 会话名小写连字符，禁空格；`<bg>` ∈ {dark, gray, wood}；class ∈ {bolt, nut, washer}。
- 裁剪图存原始分辨率（S×S 缩放发生在训练/推理管线内），64→96 升级无需重采。
- manifest 列：`frame_id, session, split, light, bg, spacing, obj_id, class, x0, y0, x1, y1, notes`。
- 2026-10-10 已增加[清单审计入口](fastener-dataset-audit.md)：frame_id 使用 `frame_00001` 一类五位文件主名，
  bbox 明确为 XYXY 半开区间；可选 `specimen_id` 用于全局实物个体隔离，不能用帧内 obj_id 替代。
  空场景保留一行条件信息，类别/目标编号/坐标/实物编号全空，仅进 test；完整格式与检查边界见入口说明。

## 5. 阴影/反光专项用例（M3 验收素材，plan.md §1.4）

| 用例 | 布置 | 判定记录 |
|:---|:---|:---|
| S1 影连件 | L1 下两螺栓沿光照方向排列，间距 = 实测最小间距 | 影子是否把两框并一框；形态/面积过滤能否拆回 |
| S2 高光分裂 | L2 下镀锌螺栓/垫圈正对光源 | 高光是否把一件裂成多框 |
| S3 影独件 | L1 下空区（只有影子、无零件） | 影子是否出框（假阳性） |
| S4 深底反光 | dark 背景 + L2 | 过暗/过曝边界样本 |
| S5 混合压力 | L3 背窗侧光 + 6–10 个混类零件 | 接近演示 worst case 的全量压力帧 |

每用例 ≥10 帧，统计漏框/多框率归档 `data/logs/<date>-lighting-stress/`；结论写明「支持条件内/外」，支持条件外 → EXE 提示复检（与 plan.md §1.4 M3 验收对齐）。

## 6. 数据审计清单（每会话收尾必过）

- [ ] 帧数、目标数与 manifest 一致；文件名可由会话名+帧号唯一还原
- [ ] 每帧 bbox 数 = GT 数；bbox 在画面内且两两不重叠（互不遮挡约束的可执行检查）
- [ ] 集合泄漏检查：任一会话只出现在一个 split；测试会话与训练会话不同日、不同布置
- [ ] 类别/光照/朝向/数量档覆盖率表已生成，缺口列入下次加采
- [ ] 抽 10 帧人工复看：AF 对焦清晰、无运动模糊、曝光正常
- [ ] 会话记录归档 `data/logs/`；运行 `sim/vision/audit_fastener_dataset.py` 完成结构、精确重复、会话/实物划分和覆盖审计。
  工具已用测试夹具离板验证；GT 对照、真实标签/清晰度/曝光、相似帧与朝向统计仍须人工核查或后续实现。

## 7. 与 board/hardware.md §4 验线的衔接顺序

1. §4 验线 PASS（base overlay 直通在采集窗口可见）→ 按 `board/logs/README.md` 留记录。
2. 用验线帧核对 Pi 锁 720p60 生效 → 执行本文 §2 机位定标。
3. §3 背景/光照/间距实测 → 回填本文 ⚠️ 项与 plan.md §1.3 待冻结参数。
4. §4 正式批次采集 → §6 审计 → 训练侧接收（docs/module3-model-training.md §3/§4，M2 节点对齐）。
5. 采集中断/异常按 `board/logs/` 只追加记录；10/5 拍板后先回填 §1 输入尺寸与 §2 门限，再开正式采集。
