# CNN 推理协处理器 RTL 开发需求

日期：2026-10-06。委托方：________；受托方：________。
本文件规定交付边界和验收方法。第8节尚待冻结的条目不构成性能或接口承诺；工作假设仅用于方案报价和设计推导。委托方须在允许编写 RTL 前书面冻结这些条目，形成随包交付的契约修订版。

## 1. 任务与系统位置

**CNN-R1**：受托方须交付从64×64×1有符号INT8小图到螺栓、螺母、垫圈三类分类结果的推理协处理器；逐目标裁剪、定位、相机接入和工单判定不属于本包。

系统流程：相机 → 预处理 → 整帧快照 → 定位外接框与按目标裁剪 → **本包CNN分类** → 按目标汇总结果。定位包产生原图坐标；本包不产生外接框。

**CNN-R2**：一次输入和结果须保持同一目标序号。委托方集成侧须保存该目标对应的来源frame_id、检查标识和config_id，按同一轮汇总结果；分类结果包含类别、分数及有效状态。过期结果不得冒充当前检查结果。

现有上游快照是8位灰度整帧流，不是已经量化的逐目标INT8小图。其帧缓冲读侧每有效拍一个像素，携带来源帧号和配置号；启动许可只在整帧启动时生效，帧内不能反压。拥塞可丢弃尚未消费帧，不能覆盖正在回放的帧。裁剪与量化适配由委托方提供，本包不直接消费这一路整帧快照。

## 2. 固定网络与算术语义

**CNN-R3**：本包须支持下表网络及三类输出；表中的空间尺寸为目标结构，padding配置在D1冻结后须确实产生这些尺寸。

| 层 | 运算 | 目标输出尺寸 | MAC数 |
|---|---|---|---:|
| 输入 | 灰度INT8 | 64×64×1 | — |
| C1 | 3×3卷积，1→16，stride=2 | 32×32×16 | 147,456 |
| C2 | 3×3卷积，16→32，stride=1 | 32×32×32 | 4,718,592 |
| C3 | 3×3卷积，32→32，stride=2 | 16×16×32 | 2,359,296 |
| C4 | 3×3卷积，32→64，stride=1 | 16×16×64 | 4,718,592 |
| HEAD | GAP，每通道空间均值；FC 64→3 | 3 | 192（FC） |
| 合计 | GAP加法及量化另计 | — | 11,944,128 |

**CNN-R4**：权重和激活采用对称per-tensor量化，zero-point=0；量化值限定在[-127,127]，以8位二进制补码存储。卷积和FC采用有符号INT8乘法、INT32累加。每个权重张量共用一个权重scale，每个激活量化点共用一个激活scale，不采用per-channel scale。

**CNN-R5**：参考量化公式为`Q(v,s)=clip(round_even(v/s),-127,127)`，其中s>0，round_even为就近舍入、恰在半整数时取偶。卷积累加A的实数解释为`A*s_in*s_w`；卷积后的参考顺序为rescale → ReLU → 按s_out requant，即`Q(max(0,A*s_in*s_w),s_out)`。硬件实现方式和scale编码按D2冻结，但不得改变冻结黄金参考的整数结果。

**CNN-R6**：FC输出参考值为`A_fc*s_fc_in*s_fc_w`，最终采用argmax判类；本包不把softmax作为既定算子。GAP舍入、bias、FC分数编码及并列argmax规则须按D3、D4冻结。

手算示例（用于说明CNN-R5公式，数值为算术示例，不是模型参数）：输入q=[2,-3]，权重q=[4,1]，A=2×4+(-3)×1=5；s_in=1/2、s_w=1/4、s_out=1/8，rescale=5/8，ReLU后requant=round_even(5)=5。若rescale为负，ReLU后输出0；若requant超过127，输出127。半整数2.5取2、3.5取4。

**CNN-R7**：目标器件为XC7Z020，目标工作时钟100 MHz（周期10 ns）；OOC报告须验证此约束。器件资源基数为220 DSP48E1、140 BRAM36；128 MAC为预算工作假设，独立DSP/BRAM/LUT上限及集成余量按D5冻结。

容量核算：不含bias的权重数为144+4,608+9,216+18,432+192=32,592字节；INT8特征图依次为4,096、16,384、32,768、8,192、16,384字节。缓存不能只按数据字节总量换算BRAM，须计入端口、位宽、分银行和碎片开销。全系统其他模块仍需占用资源。

## 3. 对外接口契约

**CNN-R8**：输入每个目标须接收4,096个INT8像素，按y递增、每行x递增排列；目标序号须锁存至本次结果完成。端口宽度、握手及元数据位宽须以D6冻结的端口表为准。

下表是D6的工作假设，供方案评审，不是已冻结端口定义。所有信号在clk上升沿采样；跨时钟适配由委托方集成。

| 假设端口 | 方向 | 假设语义 |
|---|---|---|
| clk / reset | 输入 | 100 MHz；复位极性及释放时序待冻结 |
| pixel[7:0] | 输入 | 有符号补码INT8 |
| pixel_valid / pixel_ready | 输入/输出 | 两者同时为1接收一个像素；未接收时上游保持数据 |
| target_id / image_start | 输入 | 图首锁存目标序号；位宽及与首像素关系待冻结 |
| result_valid / result_target_id | 输出 | 结果有效及对应目标序号 |
| result_class / result_score | 输出 | 类别编码与分数位宽待冻结 |

**CNN-R9**：受托方须交付配置、权重与scale加载、启动、状态查询和结果读取的寄存器级契约；MMIO或其他系统总线挂接由委托方负责。寄存器地址、数据位宽、写使能、请求/响应握手和错误响应由D7冻结。

寄存器功能表（功能必需，具体地址和位域待D7；不允许实现方自行把此表当成完整地址映射）：

| 寄存器功能 | 访问 | 必需语义 |
|---|---|---|
| 权重地址/数据/提交 | 写 | 指定层及权重位置并加载，提供完成或错误状态 |
| scale地址/数据/提交 | 写 | 加载各量化点参数，编码按D2 |
| 启动/目标序号 | 写 | 关联本次图像，启动一次推理 |
| busy/done/错误 | 读 | 区分未完成、完成与失败；清除行为按D7 |
| 结果类别/分数/目标序号/有效状态 | 读 | 返回完整同一次结果；保持及确认机制按D7 |

**CNN-R10**：运行中参数更新、重复启动、复位中断、未加载参数及像素数量错误的行为须在冻结契约逐项定义并由控制tb覆盖；结果不得包含两次推理混合的数据。

**CNN-R11**：权重hex须每行恰为两位十六进制数字，一个8位补码权重，无文件头；可由`$readmemh`加载到8位数组。逐层顺序C1、C2、C3、C4、FC；卷积索引为[out_channel][in_channel][kernel_y][kernel_x]，最后一维变化最快；FC索引为[out_class][in_feature]。单行只有一个字节，无多字节字节序歧义。正式权重包须含层偏移、元素数和校验清单。

两层手工格式示例（缩小张量，仅测试排布，不是正式网络）：层L1为1输出×1输入×1行×2列，权重[1,-2]；层L2为2输出×1输入的FC，权重[3,-4]。文件内容依次为：

```text
01
fe
03
fc
```

L1偏移0、元素数2；L2偏移2、元素数2。读回有符号值依次为1、-2、3、-4。

**CNN-R12**：scale测试包须列出每层s_w及各量化点s_in/s_out、与层的对应关系，并给出冻结编码的hex、位宽、字节顺序、舍入及溢出规则；受托方须提供加载验证。当前参考以文本实数scale表达，不能直接当作硬件hex。

D2工作假设仅为文本参考，例如两层`s_w(L1)=0.25，s_w(L2)=0.5，s_in(L1)=0.5，s_in(L2)=0.125`；正式scale hex样例须在D2冻结时补齐，本版本不虚构定点编码。

**CNN-R13**：委托方须随冻结测试包提供输入图hex、各层期望输出前64值及最终argmax，至少覆盖三张固定输入；受托方须提供逐层比对入口。输入hex采用CNN-R8顺序和CNN-R11字节表达；期望值的量化点、张量展开顺序、GAP及FC输出格式须在D8冻结。仅前64值不能证明整层正确，受托方须另用可生成完整张量的小规模算子用例验证其余索引和边界。

## 4. 性能与数据预算

**CNN-R14**：方案须按128 MAC、100 MHz的工作假设推导周期预算，分别列输入、权重读取、卷积、GAP、FC、量化、停顿及结果发布；推理延迟从启动被接受至结果有效测量，输入加载耗时另列，并报告含加载总耗时。并行重叠须说明条件，不能重复扣除时间。

11,944,128÷128=93,313.5，理想满利用至少93,314拍，即0.93314 ms；资料预算约0.95 ms/目标、约9.5 ms/10目标。这是理想计算预算，不是含控制和访存的已确定延迟上限。可测上限按D9冻结。

**CNN-R15**：受托方须对10目标/分析帧、30分析帧/秒的预算场景提供仿真或板上计时结果，报告连续处理10目标的总耗时及占帧比例。30 fps的精确周期为33.333… ms，“33 ms”仅作预算近似；0.95 ms×10约占28.5%，其余预算供定位、裁剪及调度使用，不代表这些环节已达到实时要求。

**CNN-R16**：吞吐报告须至少列输入有效字节率、加载耗时及停顿。该场景有效输入为64×64×10×30=1,228,800字节/秒；单目标4,096字节。若每拍接收一字节且无停顿，100 MHz下输入需4,096拍=40.96 μs，此值只作为接口假设核算，不是已测吞吐。权重是否常驻及加载是否计入每次推理由D5、D9冻结。

显示相机路径为720p60；30 fps是本包分析预算场景，不能据此要求显示降为30 fps，也不能声称每个显示帧均有新分类结果。

## 5. 验证要求

**CNN-R17**：受托方须交付下列自检tb，失败时返回非零退出状态，并定位层、索引、期望值与实际值。

| tb | 必测内容 |
|---|---|
| MAC | 正负乘法、[-127,127]边界、累加清零、连续累加与INT32行为 |
| 量化 | 负数ReLU、半整数取偶、上下限饱和、各scale组合及冻结编码 |
| 卷积 | 通道与权重索引、stride 1/2、冻结padding、行/帧边界 |
| GAP+FC | 均值舍入、64维FC、三输出argmax及并列情况 |
| 控制 | 参数加载、重复启动、busy/done、复位、输入不足/过量及结果关联 |
| 逐层黄金 | 三张固定输入逐层前64值及最终argmax，报告所有差异 |

**CNN-R18**：冻结后的整数量化点及最终argmax须位精确一致；FC分数按D4定义的编码比较。任何允许误差须由委托方在D2/D4书面批准，给出误差界、理由和受影响层，未批准不得用容差掩盖差异。训练演练的argmax一致不能替代正式网络逐层验证。

**CNN-R19**：受托方须提供独立交付包内的一键脚本，在使用说明列明工具、版本、依赖安装方式与命令；脚本从随包数据生成报告并执行全部tb，不依赖委托方未交付文件。通过日志须保留完整命令、参数、测试用例和原始结果。
