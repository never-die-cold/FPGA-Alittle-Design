# 修订方案：受控工业流水线紧固件检查

**版本：**方案 v2，2026-10-07  
**平台：**PYNQ-Z2（Zynq-7020），720p60 彩色相机输入  
**目标：**检查螺栓、螺母、垫圈的类别和数量，输出缺件、多件、错料及复检提示。

## 1. 方案调整依据

项目方补充：检测对象位于工业流水线，背景简单、稳定、可控，照明条件理想。基于这个工况，首版将**传统视觉定位作为主线**。之前的渐变光照反例仍保留为压力测试，用来观察超出正常工况时系统如何失败，不再用它代表流水线日常环境。

当前原型采用四角估计背景色的方法。它在新造的均匀空背景小样本上没有误检，但流水线可以主动选择和控制背景，因此正式实现应把工位条件写清楚，并验证所选颜色、照明、阴影和反光下的分割效果。若能选择传送带表面，优先选哑光、均匀、与金属零件在颜色或亮度上差异明显的颜色；例如灰色金属件配蓝/绿色哑光背景。现场材料和反射情况仍要实测。

## 2. 推荐算法结构

```text
彩色相机 720p60
   ├─显示支路：原彩色视频直通显示
   └─分析支路：按检查节拍取得一帧/一组图像
       → 背景差异分割（HSV/Lab 阈值或空台参考，实测后选一种）
       → 形态学去噪、连通区域与外接框
       → 边界/粘连/面积异常检查，异常转人工复核
       → 逐目标裁剪、灰度缩放至 64×64
       → 轻量 CNN 分类（螺栓/螺母/垫圈）
       → 按工单汇总数量，给出通过/缺件/多件/错料/复检
```

定位先用 OpenCV 作为软件黄金参考和可快速调整的基线。相机输入是彩色的，不要求定位模型使用 CNN。若选定的背景可用颜色阈值稳定分出零件，就使用更简单的阈值分割；若 RGB/HSV 阈值受金属反光影响，再比较 Lab 颜色距离或空台背景差分。参数必须从实际工位图像验证，不能仅依据屏幕观感设置。

保留小 CNN 是因为项目目标包含自研 CNN 加速器。CNN 只负责已经定位好的单个零件分类，不承担整张 720p 图像检测，输入先按硬件预算以 64×64 灰度为主。HOG/SVM 用作低成本分类参照；YOLOv8n 留作软件检测上限和异常场景对照，暂不作为首版硬件主干。

## 3. 工作节拍分两种情况

720p60 是相机/显示输入速率，不代表必须对每一帧执行一次完整检查。流水线节拍决定分析方式：

| 现场节拍 | 首版处理方式 | 额外要求 |
|---|---|---|
| 工件到位后停稳检查 | 触发采集一帧；必要时用短时间多帧中值/稳定性检查，再定位与分类 | 开始检查信号、工件静止确认、单批次防重复记数 |
| 工件持续移动 | 在固定检测区域触发/采样；将连续帧中的同一物体关联，离开区域后只记一次 | 传送带速度/方向、曝光与运动模糊、跨帧去重、目标间距、实际线速吞吐要求 |

**当前算法实验按单张稳定检查图设计。** 若生产线不停带，不能直接把单帧计数累加；需要先按线速和零件最小间距定义取像、关联和去重，再测目标板吞吐。这项节拍信息决定软件与 RTL 架构，实施连续运动版前需要现场确认。

## 4. 位置与模型的部署分工

- PL 保持现有视频直通和必要的像素预处理。显示支路保留彩色原图。
- 对受控背景，第一轮先让 PS 读取低频检查快照并运行 OpenCV 定位，快速对照算法与真实标注。若测得 PS 延迟或内存带宽不达目标，再评估将简单阈值/连通区域下沉到 PL。
- PL/CNN 协处理器执行逐目标小图分类时，必须明确小图来自哪里。不可先把整张 720p 图缩成很小，再期望从中裁出清晰零件；需要保留足够分辨率帧缓存、ROI 裁剪路径，或在 PL 中提取目标区域。
- 分类网络完成训练后，先测 FP32，再做 INT8 PTQ；若精度下降超出团队接受范围再试 QAT。整数舍入、饱和、缩放和权重排布必须与协处理器 RTL 契约一致。
- 结果携带检查/帧编号、目标框、类别、分数和有效状态，避免 EXE 把旧结果叠到当前画面。

以上是分阶段方案，不表示现有 RTL 已实现 ROI 或分类推理。板端接口与算子契约需和模块三负责人核实后才能冻结。

## 5. 数据与比较安排

1. 公开 CAD/合成图只用于早期训练流程、网络收敛和软硬件算子验证；不作最终识别效果证明。
2. 在选定背景、照明、机位上采集真实零件照片。覆盖每类的朝向、位置、大小和外观差异，并包含空场景、数量变化、错料及正常工单。
3. 按拍摄批次/实物实例划分训练、验证和最终测试，防止同一源照片、视频相邻帧泄漏。最终测试集在方案与阈值确定前保持封存。
4. 采用同一批定位框，比较灰度小 CNN 和 HOG/SVM 分类；单独报告定位误检/漏检、分类混淆、整张工单正确率和复检比例。
5. YOLO 与两阶段路线用相同真实图及相同独立测试场景比较；同时记录推理成本和能否落在 PYNQ-Z2，而不只比桌面 CPU 分数。

## 6. 验收指标建议

先记录基线，再由团队在最终验收前冻结具体门槛：

- 定位：Precision、Recall、框 IoU；分开记录空场景误报、漏件和粘连/分裂。
- 分类：按类别的混淆矩阵、每类召回率及未知/低置信度复检比例。
- 工单：正常、缺件、多件、错料的整轮通过率，以及错误工单被判通过的比例。
- 性能：从触发/目标经过检测区域到结果可用的端到端延迟；分别计定位、裁剪搬运和 CNN 时间。
- 硬件：ARM 与 PL/协处理器对同一输入的结果一致性、INT8 精度变化、资源使用和稳定运行情况。

## 7. 当前进度与下一步

已完成合成图生成、OpenCV 定位原型、HOG/SVM 与轻量 CNN 训练、YOLO 软件基准及评分工具改进。BN 折叠在 FP32 验证集上未改变分类结果。以上尚未在真实工位或 PYNQ-Z2 上验收。

下一步按优先级：

1. 确认流水线是停稳检查还是连续运动检查，并取得零件在图像中的大致像素尺寸/最小间距。
2. 按现场可选背景布置相机，采集空背景和真实零件照片，先验证 OpenCV 阈值定位稳定性。
3. 冻结 ROI 图像获取方式和 PS/PL 分工，避免全图缩放后目标细节不足。
4. 基于真实 ROI 比较 64×64 CNN 与 HOG/SVM，保留真实批次用于独立最终评估。
5. 完成 INT8 导出与 PYNQ-Z2 实测后，再决定首版最终模型和性能目标。

## 8. 本方案暂不承诺

目前没有真实相机样本、实物和板端测量，因此不宣称已达到某一工业准确率、帧率或延迟；也未完成对未知零件、遮挡、接触堆叠和连续运动目标的可靠识别。若实际需求包含这些情形，应先采集对应数据、明确节拍，再扩展方案。
