# 紧固件定位算法开发需求

日期：2026-10-06。委托方：________；受托方：________。
本文件规定定位包边界和验收方法。第7节工作假设用于方案及报价，未冻结参数不构成验收承诺；委托方须在实现依赖功能前书面冻结对应条目并回填正文和测试包。

## 1. 任务与系统位置

**LOC-R1**：受托方须交付“一帧图像 → 每个紧固件的原图外接框列表”的Python定位包。对象为螺栓、螺母、垫圈；分类、64×64×1小图裁剪/量化及CNN推理不属于本包。

系统流程：相机 → 预处理/快照 → **本包定位** → 按外接框裁剪 → CNN三类分类 → 工单检查及显示。已有ARM侧定位原型；它不构成本包性能和精度已经达标的证据。

**LOC-R2**：首版支持自由分散且互不遮挡的摆放，不以固定格子代替实际定位；任意接触、堆叠和遮挡超出支持范围。每个可确认零件应对应一个外接框；不能确认的场景须明确输出无法确认状态。

## 2. 输入、输出与环境

**LOC-R3**：定位包须在PYNQ镜像的PS侧ARM环境运行，使用Python 3和numpy/OpenCV；交付说明须列精确依赖版本、安装命令及所需镜像版本。输入为一帧numpy数组，分辨率、色彩和像素格式通过显式配置声明，格式不匹配须报错，不得隐式误读。

输入工作假设见L1：分析输入为uint8灰度二维数组，尺寸可配置；显示源为1280×720彩色720p60。显示源并不等于已经可从Python读取的分析输入。图像来自实时帧还是文件、读帧接口、预处理开关及最终分析分辨率仍待冻结。

**LOC-R4**：每次调用须显式接收frame_id，原样回传；目标target_id在该次调用中唯一，不承诺跨帧身份跟踪。结果须保留对应输入帧的关联，不能混用不同帧目标列表。config_id及检查标识如由上游提供，也须原样回传。

**LOC-R5**：输出须为可JSON序列化的结构，至少满足下表字段及类型；无目标且场景可确认时返回空targets，超出支持条件返回unable_to_confirm及非空原因。可选粗类别、置信度不替代CNN三类结果。

| 字段 | 类型 | 定义 |
|---|---|---|
| frame_id | 标识值 | 来源帧标识，保持调用者提供值；取值范围按L2冻结 |
| config_id / check_id | 可选标识值 | 上游配置/检查标识，存在时原样返回 |
| status | 字符串 | confirmed、unable_to_confirm或invalid_input |
| reason | 字符串 | confirmed时可为空；其他状态须说明原因 |
| targets | 列表 | 同一来源帧的目标列表；无法确认时不得发布为已确认框 |
| targets[].target_id | 整数 | 本帧唯一目标序号；起始值和排序按L2冻结 |
| targets[].bbox | 四个整数 | x0、y0、x1、y1，输出在原图坐标系；端点按L2冻结 |
| targets[].coarse_class | 可选字符串 | 粗类别名称或unknown；非正式分类承诺 |
| targets[].confidence | 可选数值 | 定义、范围和校准含义按L2冻结；未定义时省略 |

输出示例只说明结构；不规定目标数、坐标合格线或编码范围：

```json
{"frame_id":"source-frame","status":"confirmed","reason":"","targets":[]}
```

**LOC-R6**：受托方须按L2冻结的坐标契约输出合法、非空、图内外接框，并交付输入到原图、原图到显示的映射函数及测试。必须明确原点、轴向、端点含入规则、缩放/裁边/补边、取整规则和显示变换，不能仅给四个坐标数字。

L2工作假设：左上角为原点，x向右、y向下，框采用半开区间[x0,x1)×[y0,y1)，宽=x1-x0、高=y1-y0；满足0≤x0<x1≤W、0≤y0<y1≤H。若分析图由原图整帧等比例或分别缩放而来且无裁边/补边，映射左上端点取floor(x0*W原/W分析)、floor(y0*H原/H分析)，右下取ceil(x1*W原/W分析)、ceil(y1*H原/H分析)，并裁至原图范围。显示原图时映射为恒等；其他显示变换须由配置提供。此假设须冻结后才作为验收坐标语义。

两个包共享：定位输出原图外接框、frame_id及target_id；裁剪适配模块生成64×64×1 INT8小图并保留target_id，集成侧保存帧/配置关联；CNN只返回类别、分数、有效状态和target_id，不负责定位坐标。三类为螺栓、螺母、垫圈。

## 3. 算法与支持条件

**LOC-R7**：算法须从图像中分离候选区域、建立目标区域并输出外接框；受托方可选择具体实现，不要求固定分割器或模型。正常场景的一件零件须对应一个框，空场景须返回confirmed和空列表。

**LOC-R8**：算法须包含可配置的面积和形态过滤，参数须有单位、合法范围和使用说明；须测试阴影/反光导致的分裂、多个零件合并及背景伪目标，并分别记录错误。不能用删除困难样本的方式提高报告命中率。

**LOC-R9**：超过冻结支持条件、触碰/遮挡或存在未能解决的分裂/合并歧义时，须输出unable_to_confirm并给出原因，不得将猜测框发布为已确认结果。受托方须提供可判定触发条件和测试证据；不要求保证识别所有未知干扰。

光照强度范围、背景纹理、最小像素面积、最小间距与最大目标数均按L3冻结。自由分散且互不遮挡不等于任意背景、任意光照均支持。CNN的10目标/帧预算场景可作为定位容量评审假设，不是已确定最大目标数；没有来源数字的最小间距不设虚构值。

## 4. 性能与连续处理

**LOC-R10**：受托方须在目标ARM环境计时，报告定位纯计算耗时及含读帧/转换的调用耗时，分别列样本数、预热方法、中位数、p95和最大值；相机、显示及进程启动耗时另列，不能混成算法耗时。

**LOC-R11**：须提供连续视频处理示例和背压/丢帧策略；输出frame_id始终对应实际处理帧，丢帧不得复用旧结果作为新帧结果，无法确认和错误不得作为检查通过。是否逐帧处理、队列容量和吞吐合格线按L4冻结。

分析预算场景为30 fps，每帧33.333… ms，按33 ms近似规划；显示相机路径仍为720p60。CNN理论预算约10目标×0.95 ms=9.5 ms，33 ms扣除后约23.5 ms还须覆盖定位、裁剪、加载及调度，不能全部分配给定位。并行处理须说明依赖和重叠时段。

单帧定位耗时上限按L4冻结；当前预算工作假设为`定位上限≤33 ms−9.5 ms−裁剪/加载/调度预算`。这些附加预算尚无已确定数字，因此不把23.5 ms写成定位可承诺上限。

## 5. 测试与指标

**LOC-R12**：委托方须提供含逐物体标注框、场景支持状态和图像配置的测试包；受托方须覆盖下表所有场景并按图输出结果，正式验收不得只用合成图。测试数量、数据划分及合格线按L5冻结。

| 场景 | 检查内容 |
|---|---|
| 空场景 | 空列表，背景/阴影不误报 |
| 正常单目标 | 各支持类别出框 |
| 多目标 | 同类及异类、自由位置，一个零件一个框 |
| 不同朝向 | 各支持类别旋转摆放 |
| 反光/阴影干扰 | 伪目标、分裂、合并与无法确认行为 |
| 支持范围边界及范围外 | 光照/间距边界，接触/堆叠/遮挡的状态输出 |

**LOC-R13**：命中使用IoU≥0.5，`IoU=交集面积/并集面积`，面积按冻结端点语义计算；预测和标注作一对一最大匹配，单框不得命中多件，同一件不得被多个预测重复计命中。漏框为未匹配标注，多框为未匹配预测；另记录单件对应多框的分裂和多件对应单框的合并。分裂/合并可与漏框/多框并存，报告须说明判定依据，不能把这些列简单相加作为总错误数。

**LOC-R14**：须交付逐图结果表及汇总，至少含文件名、frame_id、标注数、预测数、命中数、漏框、多框、分裂、合并、status、原因及耗时。范围外场景单独报告无法确认正确率，不能按空场景算命中；范围内返回无法确认须单独计拒判并保留在分母中。

|---|---|

| 范围内目标精确率=命中/预测数；预测数为0时单列 | ________ |
| 空场景多框率；分裂/合并率及各分母 | ________ |
| 范围内拒判率；范围外无法确认正确率 | ________ |

**LOC-R15**：须提供一键自测入口，在独立交付包内读取测试图及标注、运行定位、计算指标、导出逐图结果和汇总；功能失败或未达冻结合格线返回非零。须保留配置、环境、命令和原始结果，不能依赖委托方未交付内容。

## 6. 交付与验收

**LOC-R16**：交付物须包括Python包、配置schema、自测脚本、带框可视化结果、逐图表、汇总报告、目标ARM原始计时、依赖说明和使用说明。接口函数须满足`locate(image: numpy.ndarray, *, frame_id, config, config_id=None, check_id=None) -> dict`；使用说明须给出可运行调用示例，config明确定义格式、坐标变换和支持条件参数。

**LOC-R17**：验收须逐项检查R3环境与输入错误处理，R4—R6帧/目标及坐标契约，R7—R9空场景/正常/歧义行为，R10—R11冻结性能和连续处理，R12—R15测试覆盖与冻结合格线，R16包内独立调用。未填写L5合格线不得认定精度验收完成。

**LOC-R18**：若受托方方案涉及任何RTL，在编写RTL前必须提交数据通路框图、权重/特征图/行缓存等片上缓存BRAM分配（不适用项说明原因）、与第4节对账的周期预算和风险清单，取得委托方书面确认。纯ARM方案不扩大为PL开发；平台分配变更须同步范围和验收要求。

交付节奏由委托方填写：T为测试包及契约冻结日；方案T+N个工作日，算法包与自测T+N个工作日，目标ARM复测及修订T+N个工作日。
