# 模块三模型训练前期准备（INT8 CNN 训练与量化路线）

> 是什么：模块三 CNN 推理协处理器对应的**训练侧**前期准备文档——训练/量化路线选型、交付物定义与接口对齐点。
> 给谁看：never-die-cold（训练侧准备，经 9/29 授权）、jianglibo（`src/coprocessor/` RTL，第 5 节对齐点）、watercopper（第 6 节测试数据衔接）。
> 什么时候读：紧固件数据准备、模型选型与协处理器契约评审时；契约定稿后回填第 5 节。
> 状态：前期草案，不约束 RTL；RTL 与算子自测以 jianglibo 的契约为准。

## 1. 目标与交付物定义

训练侧最终交付四样东西（均为协处理器可用格式）：

1. **定点模型**：INT8 权重 + INT8 激活（含 scale/zero-point 参数表）；
2. **权重 hex 导出**：位宽、排布（逐层/逐通道）、初始化文件格式——参数化脚本，具体排布等 `cop_top` 契约回填；
3. **精度报告**：浮点基线 vs INT8 的 top-1/精度差，作为"模型训练之类的"验收证据；
4. **黄金参考**：逐层 activation 数值抽查（若干输入图、每层前 64 个输出），供 watercopper 做协处理器逐层比对测试数据。

## 2. 量化路线选型（推荐 + 备选）

| 路线 | 做法 | 优点 | 风险 |
|:---|:---|:---|:---|
| **QAT（推荐）** | PyTorch `torch.ao.quantization` 量化感知训练，或 Brevitas（FINN 生态，主计划列为架构参考） | 激活范围提前校准，精度损失需实际测量 | 训练周期略长 |
| PTQ（备选） | 训练后校准量化（少量校准集） | 最快出结果 | 小网络也会掉点，且校准集要凑 |

结论倾向：**Brevitas + QAT**，理由：与 FINN 部署流同生态；导出的量化参数仍须与硬件 INT8 MAC 契约核对。若环境受阻，降级用 torch.ao QAT，导出脚本隔离框架差异。

✅ **路线演练通过（2026-10-03）**：brevitas 0.13.4 + torch 2.14 CPU。QAT 训练收敛（acc 1.00）后导出 INT8 权重 + scale，按**整数累加语义**（int8×int8→int32 累加→rescale→requant，即 MAC 阵列口径）独立复现，argmax 100% 一致。脚本 `data/scripts/m3_brevitas_drill.py` 一键复现，证据 `data/logs/2026-10-03-m3-brevitas-drill/`。接口注意：brevitas 0.13 无 `layer.quant_input_scale` 属性，激活 scale 须用 `QuantIdentity` 显式量化点持有（`IntQuantTensor.scale`），不碰框架内部 API。

## 3. 紧固件任务、网络与数据准备

- 网络规模约束：x7z020 资源 + INT8 MAC 阵列规模（等契约），候选为轻量级分类/检测头（层数 ≤8 卷积级、通道 ≤64 量级）；
- 对象已确定：真实 HDMI 相机下的螺栓、螺母、垫圈；结果在 Windows EXE 中以物体框、类别标签和工业统计展示。正式定位与识别模型尚未实现。
- 摆放已确定为自由分散且互不遮挡；路线为传统视觉定位 + CNN 分类：分割/连通区域定位 → 按物体外接框裁剪 → 小图分类。矩形坐标来自定位算法，不由分类网络输出；不采用固定格子假设或端到端检测网络作为首版主线。
- 数据以实际相机拍摄为主，覆盖朝向、光照、位置及空场景；按实物与拍摄批次划分训练/验证/测试，避免相邻视频帧混入各集合。数据规模与精度门槛在采样试验和算子契约确定后冻结。
- 模型与采集预处理一致：裁剪、灰度/彩色、缩放、归一化和量化语义需要对齐；物体坐标映射回显示画面。FP32/INT8 精度和定位效果分别报告，工单误报/漏报由端到端测试评估。EXE 由 `watercopper` 负责，使用同一轮的坐标与类别结果显示。
- 前期演练用途：跑通环境与“训练→INT8→hex 导出”，不作为正式紧固件模型或目标检测验收。
- **✅ 演练已完成（2026-09-30，torch 2.14 CPU）**：`data/scripts/m3_train_drill.py` 一键复现（`python data/scripts/m3_train_drill.py`），输出归档 `data/logs/2026-09-30-m3-train-drill/`。结论：链路可行——极简 CNN 训练收敛（acc 1.00）、手工 per-tensor 对称 INT8 量化后与 FP32 argmax 100% 一致、2740 权重导出 hex + scales + 逐层激活 golden。演练暴露的接口细节：① torch Sequential 参数名带占位索引（0/2/5），导出脚本必须显式层名映射，不能按 conv 序号拼；② 量化语义（对称 per-tensor、权重 [-127,127]）已按协处理器 MAC 阵列口径实现，`cop_top` 契约冻结时若改 per-channel/zp 需同步改演练脚本。

### 3.5 D5 拍板材料：输入尺寸与 MAC 阵列预算（2026-10-03，供 10/5 评审，拍板权在模块三）

依据（仓库内可查）：

- x7z020 有 220 DSP48E1、140 BRAM36；**视觉链 OOC 实测 DSP 占用 0/220**（scaler/gaussian/sobel 全 LUT 实现，`data/logs/2026-09-30-scaler-retiming/`、`data/logs/2026-10-01-vision-m2-sprint/` utilization 报告）——DSP 几乎全数可留给 MAC 阵列（RISC-V 核 muldiv 若占 DSP 另扣，量级个位数）；
- BRAM：视觉全链 ≈10（NLINES=8）~22（NLINES=32）BRAM36（10/5 决策单 D5 估算），总量 140 余量大；
- vision 侧硬约束（决策单 D5）：NLINES ≥ 720/DH + 2，取 2 的幂——DH=64→NLINES=16，DH=32→NLINES=32，96×96 同样落在 NLINES=16 档。

候选首网草案（1 通道灰度输入、≤5 卷积级、通道 ≤64，逐目标小图分类）：

| 级 | 结构 | 输出特征图 | MAC 数/目标（64×64 输入） |
|:---|:---|:---|:---|
| C1 | 3×3 conv 1→16, s2 | 32×32×16 | 0.15 M |
| C2 | 3×3 conv 16→32, s1 | 32×32×32 | 4.7 M |
| C3 | 3×3 conv 32→32, s2 | 16×16×32 | 2.4 M |
| C4 | 3×3 conv 32→64, s1 | 16×16×64 | 4.7 M |
| HEAD | GAP(64)→FC 64→3 | 3 类 | ≈0.2 K |
| 合计 | | | **≈12.0 M**（32×32 输入 ÷4；96×96 ×2.25） |

MAC 阵列规模预算（@100 MHz，INT8）：

| 阵列 | DSP 占用 | 64×64 单目标延迟 | 10 目标 @30fps 占帧预算（33 ms） |
|:---|:---|:---|:---|
| 8×8=64 | 64/220≈29% | ≈1.9 ms | ≈19 ms（贴线） |
| **8×16=128（推荐）** | 128/220≈58% | ≈0.95 ms | ≈9.5 ms |
| 16×16=256 | 需 2 MAC/DSP 打包（裸算 116% 超额） | ≈0.5 ms | ≈5 ms |

建议（供拍板，非拍板）：**输入 64×64 起步 + MAC 阵列 8×16=128**。理由：①DSP 实测 0 占用下 128 无资源压力；②64×64 落 NLINES=16 档，比 32×32 的 32 槽省一半行缓存 BRAM，还给 CNN 多一倍分辨率；③10 目标 @30fps 占帧预算 ~30%，为定位/裁剪/调度留余量；后续精度不足可升 96×96（NLINES 不变，延迟 ×2.25 仍可行）。224×224 保留上限仿真档（D5 原口径）。
待核风险：①全系统 LUT 时序裕量（D1 记录 ~2% 贴线）与 BRAM 复核以集成后 utilization 为准；②权重总量 ≈0.33 MB（候选网），片上缓存充裕但排布待 cop 契约（§5.1）；③量化语义已由 10/3 Brevitas 演练钉住（对称 per-tensor、权重 [-127,127]、int32 累加），对应 §5 对齐点 1/3 的训练侧口径。

## 5. 与 jianglibo（cop_top RTL）的对齐点（契约冻结时必须回答）

1. 权重位宽/排布：每 MAC 通道的权重存储格式、是否逐层独立 BRAM、初始化文件是 `$readmemh` hex 还是运行时 AXI 写入；
2. 激活量化参数（scale/zero-point）存哪：RTL 常量、参数寄存器还是权重文件头；
3. 支持的算子边界：有无 bias 加法、ReLU/截位方式、padding 策略（影响网络结构选择）；
4. MAC 阵列维度（并行度）→ 反推训练侧可接受的最大通道数/核尺寸；
5. 推理完成信号与结果回读方式（A3 同屏对比依赖）。

## 6. 与 watercopper（测试数据）的衔接

- 逐层黄金参考格式：输入图 hex + 每层期望输出切片，命名随 cop 契约定；
- 端到端黄金：固定 3 张输入图的最终分类/检测结果，作为 `tb_cop` 与板上演示的判据数据。
- 工业闭环测试另覆盖空场景、正常工单、缺件、多余件、错料及无法确认的画面；模型黄金与工单规则测试分开，不能只用三张图片宣称泛化精度。
