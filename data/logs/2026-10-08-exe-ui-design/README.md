# EXE HUD 设计提案（2026-10-08，草案待评审，未提交）

用户反馈：现有界面美观不足（比赛场景，第一印象重要）；方向 = 科技感 + 贴合工业检查实际
+ 关键信息醒目 + 不花哨（矫枉过正）。

## 调研结论（两路来源一致）

- **NASA HUD 军标 declutter 原则**："没有一个像素可以白亮——每个元素必须证明它值得出现在
  屏幕上"；关键信息大而持续，装饰性内容一律砍掉（正对应"不要花里胡哨"）。
- **硬科幻视觉设计参考**点名批评"小黑条 + 绿色等宽字体 + 孤立数字"的默认公式——正是现状
  （01_current.png）；推荐角括号、一致的字体层级（1 字体 × 3 号）、受控调色板。
- **工业视觉检测 UI 行业惯例**（多家检测软件界面拆解）：深色底 + 青/蓝主色 + 绿 OK / 红 NG；
  大字号适合远观；运行时界面少文字、高对比。
- **冗余编码**：关键状态不能只靠颜色（色差/色盲），需"颜色 + 形状 + 文字"多通道。

## 设计要点

1. **模式徽标（左上，实心琥珀"MOCK ONLY"）**：任何界面状态下对比度最高——"mock 不得当板端
   识别"红线在视觉上不可忽视；LIVE 模式下换绿色徽标。
2. **信息框 = 半透明衬底 + 细边框**（v2 加边框，v3 去四角刻线）：左上状态框与右上指标面板
   都有明确边界；科技感来自"结构"（边框、留白）而非特效。
3. **指标面板（右上）**：ROUND / TARGETS / REC / AGE 四格大数字；面板下沿**新鲜度条**
   （青色按年龄收缩、过期转红）——仪表感 + 把"结果新鲜度"变成一眼可见的量。
4. **目标框 = 实线绿方框 + 序号片**（v3 定稿：实线方框比角括号"更有感觉"）：颜色 + 形状 +
   文字三重编码。
5. **状态语义色**：绿=有效 / 琥珀=等待 / 红=故障；等待状态同时"撤框 + 数值置 -- + 状态文字"
   （三重冗余）。
6. **等待文字用深琥珀 #F09600 且置于深色衬底框内**（用户反馈"亮琥珀落在浅底发虚"）：
   只调深文字在深色视频背景下会反向失效；衬底框保证亮底/暗底都可读。
7. **REC 常驻计数**保留（工程仪表化，操作反馈可见）。

## 实现映射（OpenCV，全部可落地，无新依赖）

- 半透明面板：仅面板 ROI 内 `addWeighted(base, α, roi, 1-α)`——不全屏混合，性能可控
- 角括号：每角两条 `cv2.line`
- 文字：`FONT_HERSHEY_DUPLEX` + `LINE_AA`；**仅支持 ASCII**
- ⚠ 字形陷阱（本次已踩）：`·` `×` `—` 等非 ASCII 字形在 Hershey 字体渲染为问号框
- 中文类别名（M3：螺栓/螺母/垫圈）：需 Pillow 用系统字体预渲染贴图（列为 M3 项，
  新增轻依赖 + 打包带字体文件）
