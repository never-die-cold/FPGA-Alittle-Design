# EXE 识别范围表改版：交互设计与两轮布局评审（2026-10-17）

> owner 板端联调后提出两个前端问题，以渲染图两轮评审定稿；本目录为设计记录与复现入口。
> 关联提交：`7335008`（表格 + 交互 + 按钮反馈）、`9ceb7e6`（面板移入右侧栏顶部）。

## 问题（owner 实测反馈）

1. 右下角 `RUN INSPECTION` 按钮"无法交互（按了没反应）且放置意义不明"；
2. 右上角状态栏（ROUND/TARGETS/REC + FRESHNESS）遮挡画面；要求改为可交互表格：
   **左类别 / 中勾选框（勾选 = 希望识别该类工件）/ 右数目，FRESHNESS 在下**；"美观很重要"。

## 诊断

- 按钮点击链路实际可用；"没反应"是三重叠加：板端一轮约 2 分钟且**期间零反馈**、按钮孤悬在
  侧栏空白区无视觉关联、无悬停提示。修正方向是**即时状态反馈**，不是改触发逻辑。
- 遮挡问题第一轮评审（面板浮动于视频右上、收窄至 340px、轻透明）后 owner 仍不满意；
  第二轮将整表**移入右侧栏顶部**，画面完全无遮挡——**浮动面板收窄/透明只是缓解，移出内容区才是解决**。

## 设计决策（已实装）

- **识别范围表**：三行类别（bolt/nut/washer）：勾选框 / 类别名 / 计数（该类别已分类目标数；
  `LOCATION_ONLY` 或无有效结果显示 `--`）；行悬停高亮；标题下 `ROUND n · REC m` 注记。
- **勾选语义（当前）**：本地显示/跟踪过滤——未勾选类别不画框、不进对象列表（**T 序号保留
  目标原始编号，不重排**）；计数列仍灰显其数目，不隐瞒；工单下发到服务端待 C04 §6 评审后
  另行实现。`--scope bolt,nut` 可预设初始勾选。
- **RUN 按钮**并入表内，三态即时反馈：青色 IDLE → 琥珀 `QUEUED · WAITING` → 暗底 `RUNNING`
  （数据源 `rounds.AsyncRemoteRounds.manual_in_flight` + `manual_pending`；点击 / 按 `c` 等效）。
- **配色约束**：面板区不使用绿色——绿色专属目标框，保证打包测试"绿像素 = 有目标框"的
  内容断言不被 UI 污染（勾选态用品牌青）。
- **列表压缩**：`DETECTED OBJECTS` 移至表下，3 张紧凑卡片（116 高 / 126 间距）+ `+N more`。
- FILE REPLAY 复用同一表格（只读：无勾选框，计数为"实际 / 工单"）。

## 已知边界

- 勾选只作用于**本地显示**；不下发到板端服务（协议新增字段须走 C04 §6 版本评审）。
- `--scope` 仅预设初始勾选；运行中勾选由鼠标点击/悬停即时切换。
- UVC-only 模式（无 `--endpoint`）不显示该面板（无结果可显示）。
